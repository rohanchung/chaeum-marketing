## 2. 확정된 제품 모델

### 대시보드 구조

헤더는 로고 / 대시보드 / 콘텐츠 / 이벤트 / 분석 / 리포트 / 로그아웃만 둔다.
대시보드 상단은 달력(월 선택 및 이동) / 이번 달 / 빠른 입력만 둔다. 별도의 '26년 9월 운영 현황' 제목은 제거한다. 그 아래 KPI 카드는 유지한다.

메인은 가로 날짜 타임라인 입력표다. 왼쪽에 대상과 세부 지표, 그 옆에 월간 합계, 오른쪽에 날짜별 셀이 있어야 한다. 날짜를 행으로 나열하는 사건별 테이블은 불편하다고 명시적으로 거절했다.

왼쪽 구조:

```text
학원 전체 퍼널
  유입 / 카카오 상담 / 전화 상담 / 방문 상담 / 등록
로한이 등록한 채널 A (예: 인스타그램)
  소재 A
    채널 템플릿의 세부 지표 → 월 집계 + 날짜별 입력 칸
  소재 B
로한이 등록한 채널 B (예: 네이버 블로그)
  소재 C
```

- 고정 '유료 광고 / 콘텐츠' 상위 그룹은 완전히 제거한다. 채널이 직접 최상위 카테고리다.
- 학원 전체 퍼널 외에 에이전트가 임의로 고정 카테고리를 만들지 않는다.
- 채널은 로한이 추가·조회·수정·삭제한다. 실제 DB에 있는 채널/성과를 임의로 모두 삭제하라는 뜻으로 확대 해석하지 않는다.
- 퍼널 지표 항목도 CRUD 대상이다. 데이터 셀만 수정 가능한 것으로 끝내면 안 된다.
- 채널, 소재, 지표 항목, 일별 값 등 보이는 관리 대상 전반의 CRUD가 필요하다.
- 엑셀 수준으로 편한 직접 입력이 핵심. 페이지 왕복과 불필요한 모달을 줄인다.

### 채널·소재·유료 집행

- 유료/무료는 채널을 분류하는 기준이 아니다. 인스타그램 등 하나의 채널에 일반 콘텐츠와 광고 집행이 공존한다.
- 소재를 만들 때 기본 템플릿으로 지표 행과 일별 셀이 자동 생성되어야 한다.
- 무료 소재에는 광고 비용 계산 행이 없다. 유료 집행에는 지출 및 광고 효율 계산용 원시 지표를 기록한다.
- 기존 무료 소재를 클릭하면 상세 모달이 열리고, 유료 집행 시작일/종료일을 지정할 수 있어야 한다.
- 같은 소재에 여러 집행 기간이 붙을 수 있다. 광고를 시작한다고 소재를 복제하지 않는다.
- 지정 기간에 광고 성과·비용 입력이 활성화되어야 한다. 종료해도 과거 값은 보존·조회한다.
- 게시물 전체 성과에 광고 성과가 포함될 수 있으므로 단순 합산하지 않는다. 유기적 성과와 광고 성과의 실제 제공 범위를 확인해 구분한다.

### 지표 템플릿

- 당근 이미지: 노출수, 클릭수, 반응수, 총 지출. 클릭률, 반응률, 반응당 지출은 파생 지표. 광고그룹 총합과 소재별 수치가 함께 제공된다.
- 인스타 이미지: 조회수, 도달, 게시물 반응(공유·좋아요·댓글·저장), 프로필 활동(프로필 방문·외부 링크 누름·비즈니스 주소 누름).
- 블로그 지표는 실제 제공 화면에 맞춰 확인할 것. 과거 에이전트가 언급한 검색 유입/링크 클릭 등은 모든 게시물에서 제공된다고 검증된 사실이 아니다.
- 채널에 템플릿을 설정하면 소재의 하위 지표가 자동 생성된다. 항목 추가·수정·삭제도 가능해야 한다.
- 누적 스냅샷을 매일 더하면 안 된다. 로한은 누적값의 비합산 집계를 수긍했다. 단 '최종값'과 'MAX'는 서로 다르며, 수치 정정/감소와 월간 증가분을 고려해 의미를 명확히 해야 한다.
- 비율·단가는 원시 수치의 합계로 재계산. 행별 비율을 단순 합산/평균하면 안 된다.

### 소재 수명주기

- 아카이브와 삭제는 별개 버튼이다.
- 아카이브: 대시보드 입력표에서 숨기고 콘텐츠 목록에 남긴다. 과거 지표/비용/집행 이력과 보고서는 보존. 다시 복원할 수 있다.
- 삭제: 확인 후 휴지통(soft delete)으로 이동하고 복원 가능하도록 합의했다. 연결 실적의 리포트 제외 정책은 일관되게 적용해야 한다.
- 콘텐츠 메뉴에서 운영 중 / 아카이브 / 휴지통을 관리한다.

### 이벤트·성과·기타

- 설명회, 커피차, 방송 출연, 협업 등은 사건/이벤트다. 별도 고정 채널로 강제 분류하지 않는다.
- 별도의 대시보드 이벤트 박스를 만들지 않는다. 타임라인 날짜 클릭 → 해당 날짜 사건 기록 → 이벤트 메뉴에서 목록 확인.
- 상담은 학원 전체의 카카오톡 플러스친구, 전화, 방문 상담. 등록도 학원 전체 일일 값이며 채널별로 강제 귀속하지 않는다.
- 궁극적으로 채널/소재/사건과 전환·매출의 연관성, 효율 분석이 목적이다. 근거 없는 기여도 추정은 피하고 미확인은 미확인으로 남긴다.
- 제작물·굿즈·광고 콘텐츠 제작비도 관리 대상. 유지/퇴원은 범위 밖.
- 기록 영구 보존/백업, 기간별 PDF·Excel 보고서와 그래프 필요. 노션은 대표와 업무 공유용이므로 이 앱에서 노션 업무 트래커를 복제하지 않는다.
- 나중에 회사 SaaS에 통합할 수 있도록 기능/데이터 문서와 이관 구조를 남긴다.

## 4. 실제 구현과 중단 직전 변경

현재 코드에 로그인, 월별 표, 퍼널 수기 입력, 채널/소재 생성, 채널 이름 수정/soft delete, 콘텐츠 라이브러리, 소재 아카이브/복원/휴지통, 날짜 클릭 이벤트 생성 및 해당 월 이벤트 목록이 있다.

중단 직전 `page.tsx`에 적용한 미커밋 패치:

1. `expanded` 초기값의 `paid`, `content` 제거.
2. `rows`의 고정 유료광고/콘텐츠 그룹 생성과 profile별 채널 필터 제거.
3. `channels.forEach(channel => appendRows(...))`로 모든 등록 채널 직접 나열.
4. 채널/소재의 기본 펼침을 `expanded[id] !== false`로 변경하고 토글도 이에 맞게 변경.
5. 채널 설명을 '지표 템플릿' 문구로 정리, 빈 소재 행 안내 변경.

이 패치는 도구상 성공했으나 사용자가 턴을 중단해 타입 검사/빌드/실제 화면 검증은 아직 안 했다. 인수인계 요청 이후 추가 기능 개발은 진행하지 않았다.

남은 직접적인 레이아웃 문제: `appendRows`의 채널은 여전히 `type: asset`, `indent: 1`, 소재는 indent 2, 지표는 indent 3이다. 최상위 채널은 indent 0으로 조정하는 것이 요구에 맞다. GridRow의 화살표는 아직 `expanded[row.id] ? ...`라 기본 펼침 상태와 아이콘이 어긋난다. 대시보드에서 채널 CRUD 진입점도 확인할 것(현재 콘텐츠 관리 페이지에 이름 수정/삭제가 있음).

## 5. 반드시 고쳐야 할 미완료/위험 사항

### 지표 데이터 충돌 (최우선)

`valueFor`는 clicks→inflows, reactions→consultations, 그 외 모든 콘텐츠 지표→impressions로 읽는다. `saveCell`도 같은 방식으로 쓴다. 즉 인스타 조회·도달·좋아요·댓글·저장 등이 독립 값으로 저장되지 않고 같은 칼럼을 덮어쓴다. 화면에 여러 행이 있다고 기능이 구현된 것이 아니다. 지표별 저장 모델과 마이그레이션을 먼저 바로잡을 것. 기존 값은 어떤 지표였는지 판별 불가능할 수 있으므로 자동 추정해 덮어쓰지 말 것.

### 유료 기간/소재 모델 미완료

- `content_promotions`는 SQL 파일만 작성했고 원격 적용 확인이 없다.
- 소재 상세 모달의 기간 설정/수정/삭제 UI, 기간별 광고 지표 입력, 프로모션별 원시값 저장은 미구현.
- 생성 시 무료/유료 선택은 여전히 `content_type = post / ad_creative` 저장 정도다.
- `appendRows`의 지표는 아직 채널 profile로 결정한다. 소재의 무료/유료와 집행 기간이 반영되지 않는다. 따라서 '유료 여부를 소재로 옮겼다'는 이전 답변은 부분 구현을 과장했다.
- profile 함수는 measurement_template의 기본값 custom을 먼저 반환해 기존 당근/인스타 이름 추론을 차단할 수 있다. 실제 저장값 확인 필요.

### CRUD/화면 미완료

- 퍼널 지표 항목과 채널 템플릿 지표 CRUD 미구현(하드코딩).
- 소재 제목/메타정보 수정 및 상세 모달 미구현. 채널 수정도 이름 prompt 수준.
- 채널 삭제 후 이름을 찾지 못하는 연결 소재는 '연결 채널 없음'으로 보여 과거 소속 정보 UX가 약함.
- 분석 메뉴는 실제 분석 화면이 아니라 대시보드로 떨어질 수 있음. 메뉴마다 실동작 확인.
- 아카이브는 status만 갱신. archived_at/reason 칼럼은 사용되지 않는다.
- 이벤트 목록은 현재 선택 월만 로드되는데 페이지 자체의 기간 탐색과 CRUD는 불충분.

### 저장/집계/보고서 검증 부족

- 동일 일자 퍼널 저장을 upsert로 바꿨지만 실제 로그인한 클라이언트 권한으로 저장→재조회 검증하지 않았다.
