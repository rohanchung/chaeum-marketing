# 로한 마케팅 대시보드 UI/UX 개편 기획서

작성일: 2026-09-23  
상태: **구현 전 검토 초안**  
범위: `대시보드` 화면만. 업무·프로젝트 관리 기능을 이 화면에 다시 넣지 않는다.

## 1. 개편 목적

대시보드는 로한 마케팅의 **일일 기록과 월간 성과 확인을 동시에 하는 운영 시트**다. 사용자가 매일 수치를 빠르게 입력하고, 월말에는 같은 화면에서 유입·상담·등록·비용·수납의 흐름을 확인할 수 있어야 한다.

향후 채널, 소재, 광고 집행, 키워드, 지표가 늘어도 카드가 계속 늘어나거나 표의 의미가 흐려지지 않도록 Football Manager의 정보 화면처럼 **표의 행·열·그룹·요약 행**으로 관리한다.

> 카드 = 한 번의 행동이나 간단한 요약을 담는 단위  
> 표 = 계속 쌓이는 운영 데이터를 관리하는 단위

## 2. 현재 구성 점검

현재 구현은 아래 구조다. 핵심 데이터 계약과 직접 입력 방식은 유지할 수 있는 상태다.

| 구간 | 현재 구성 | 유지할 점 | 정리할 점 |
| --- | --- | --- | --- |
| L1 | 로한 마케팅 로고와 전역 메뉴 | 상단 고정, 현재 메뉴 강조 | 대시보드 내부 제어를 L1에 섞지 않음 |
| L2 | 저장 상태, 이전·다음 월, 월 선택, 오늘, `＋ 빠른 입력` | 월 전환과 빠른 입력의 접근성 | 저장 상태와 기간·입력 행동의 위계를 더 명확히 정리 |
| 성과 요약 | 유입, 상담, 등록, 마케팅 비용, 순수납 매출 KPI 5개 | 학원 전체 성과를 채널 수치와 분리 | 큰 카드 면적을 줄이고 수치를 표처럼 한 줄에서 비교 |
| 운영 시트 | 고정된 `운영 대상/지표`, `월간 요약`, 일별 열 | 가로 날짜 입력, 오늘 강조, 열 너비 조절, 붙여넣기, 키보드 이동 | 그룹의 단계와 대표 지표의 의미를 더 선명하게 표시 |
| 운영 시트 행 | 학원 전체 퍼널 → 채널 → 채널 직접 지표 → 소재/키워드/비즈프로필 → 광고 집행 → 학원 전체 마케팅 성과 | 실제 데이터 구조와 정확히 연결됨 | 채널·소재·지표가 많을 때 첫 화면의 밀도를 통제 |
| 이벤트 | 날짜를 눌러 기록하고, 시트 첫 행에 일자별 이벤트와 원가 표시 | 이벤트가 채널로 섞이지 않음 | 이벤트 행을 고정된 맥락 행으로 더 명확히 구분 |
| 보조 행동 | 되돌리기, 비용 원장, 매출 기록, 아카이브, 채널 추가, 삭제 지표 복원 | 기능을 유지 | 기본 화면에서는 필요한 행동만 보이고 나머지는 더보기로 수렴 |

현재 데이터 입력과 계산은 이미 다음 원칙을 따른다. 이번 개편은 이 원칙을 바꾸지 않는다.

- 빈 값과 실제 `0`은 다르게 유지한다.
- 비율은 원시 지표에서 자동 계산하며 직접 입력하지 않는다.
- 순위는 합산하지 않고 최신·최고·변동 기준으로 표시한다.
- 상담·등록은 학원 전체 퍼널에서 한 번만 기록한다.
- 마케팅 비용은 지급 원장, 포함을 선택한 지표, 구매 비용의 중복 없는 합계다.

## 3. 현재 화면에서 해결할 문제

1. 월간 핵심 성과가 넓은 카드 다섯 장으로 나뉘어, 날짜 운영 시트보다 화면의 세로 공간을 더 많이 차지한다.
2. `빠른 입력`, 채널 추가, 복원, 아카이브, 원장 이동처럼 성격이 다른 행동이 서로 다른 위치에 흩어져 있다.
3. 채널과 소재가 늘어날수록 어떤 행이 입력 행이고, 어떤 행이 상위 요약 행인지 즉시 구분하기 어렵다.
4. 채널별 대표 지표를 접힌 상태에서 비교하는 기능은 있으나, 선택한 대표 지표와 월간 요약의 관계가 더 선명하게 보여야 한다.
5. 운영 시트가 핵심인데도 현재 제목·도움말·행 색·작업 버튼의 밀도가 서로 일관되지 않다.

## 4. 설계 원칙

### 4.1 한 화면, 한 운영 흐름

`기간 선택 → 오늘/월간 성과 확인 → 수치 입력 → 채널·소재 상세 확인 → 비용·매출 원장 확인` 순서가 위에서 아래로 자연스럽게 이어져야 한다. 별도의 대시보드 카드나 우측 패널로 동일 데이터를 반복하지 않는다.

### 4.2 표를 기본 화면으로 둔다

- 화면의 주 영역은 항상 운영 시트다.
- 채널, 소재, 광고 집행, 키워드는 부모·자식 행을 들여쓰기로 표현한다.
- 그룹 행은 접기/펼치기와 대표 지표 요약을 제공하고, 실제 숫자는 하위 지표 행에만 입력한다.
- 상세 설정, 생성, 삭제, 복원은 모달 또는 행의 `⋯`에 둔다. 상시 노출되는 버튼 수를 줄인다.

### 4.3 밀도는 높이고, 가독성은 행의 위계로 만든다

- 기본 간격은 4px·8px·12px 단위로 제한한다.
- 한글 레이블은 왼쪽, 숫자는 오른쪽, 날짜·비율은 가운데 또는 오른쪽으로 정렬한다.
- 흰색·아주 옅은 회색을 기본으로 쓰고, 채널 색상은 해당 채널의 그룹 행·선택 상태·미세한 배경 농도에만 쓴다.
- 경고·오류·마감 의미가 아닌 색을 경고 색처럼 사용하지 않는다.

### 4.4 입력은 빠르고 안전해야 한다

- 현재의 Enter/Tab/방향키 이동, 범위 붙여넣기, 자동 저장, 실패 시 원복을 유지한다.
- 입력 가능한 값과 자동 계산 값은 배경과 커서 반응으로 분명히 구분한다.
- 날짜 열, 왼쪽 문맥 열, 월간 요약 열은 스크롤 중에도 고정한다.

### 4.5 대시보드와 업무의 책임을 나눈다

- 대시보드: 마케팅 운영 수치, 이벤트 표시, 비용·매출·전환 연결.
- 업무: 캘린더, 프로젝트, 업무 카드, 체크리스트, 일정 실행.
- 이벤트는 두 화면에서 같은 기록을 사용하지만, 대시보드에는 날짜별 운영 맥락으로만 표시한다.

### 5.2 L2: 기간과 입력 제어

| 요소 | 위치 | 동작 |
| --- | --- | --- |
| 저장 상태 | 왼쪽 | 마지막 **성공 저장 시각**과 상태를 짧게 표시한다. `저장·조회 중`, `확인 필요`일 때만 색과 문구를 바꾼다. |
| 월 이동 | 오른쪽 | 이전·다음 월, 월 선택, 오늘 버튼을 하나의 조작 그룹으로 둔다. |
| `＋ 입력` | 가장 오른쪽 | 소재, 비용, 고객·전환, 결제·환불, 이벤트, 채널 추가를 여는 단일 메뉴다. 버튼 이름은 `＋ 입력`으로 짧게 유지한다. |

### 5.3 L3: 월간 성과 스트립

현재 5개 KPI의 값과 계산은 그대로 쓰되, 큰 독립 카드 대신 한 줄의 **성과 스트립**으로 바꾼다.

| 순서 | 지표 | 표시 규칙 |
| --- | --- | --- |
| 1 | 학원 유입 | 학원 전체 일일 집계 |
| 2 | 상담 건수 | 학원 전체 퍼널의 상담 |
| 3 | 신규 등록 | 학원 전체 퍼널의 등록 |
| 4 | 마케팅 비용 | 지급 완료 기준의 중복 없는 비용 합계 |
| 5 | 순수납 매출 | 등록 관련 결제 − 환불 |

- 모든 수치는 같은 높이의 셀로 나누고, 수치가 큰 항목만 약하게 강조한다.
- ROI·객단가는 대시보드 성과 스트립에 억지로 늘리지 않는다. 서비스 원가·결제 고객 수 등 판단 맥락이 필요한 지표이므로 분석 화면의 주 지표로 둔다.
- 항목을 누르면 새 카드를 열지 않고 해당 데이터가 있는 시트 그룹 또는 분석 화면으로 이동한다. 이 동작은 구현 단계에서 실제 이동 대상이 확정된 뒤 넣는다.

### 5.4 운영 시트의 행 위계

| 단계 | 행의 역할 | 배경/글자 | 기본 상태 |
| --- | --- | --- | --- |
| 0 | 이벤트, 학원 전체 퍼널, 채널, 학원 전체 마케팅 성과 | 굵은 글자, 옅은 그룹색 | 퍼널·마케팅 성과는 펼침, 채널은 최근 입력 상태를 기억 |
| 1 | 채널 직접 지표, 소재, 비즈프로필, 키워드 그룹 | 한 단계 들여쓰기, 아주 옅은 색 | 소재는 접힘, 비즈프로필은 채널 성격에 따라 유지 |
| 2 | 소재 자연 지표, 광고 집행, 키워드 | 두 단계 들여쓰기 | 소재를 열 때만 노출 |
| 3 | 실제 입력 지표와 비용 원장 행 | 세 단계 들여쓰기, 숫자 입력 셀 | 상위 행이 펼쳐졌을 때 노출 |
| 계산 | 클릭률, 월간 요약, 상담당 비용 등 | 옅은 텍스트, 편집 불가 | 관련 입력 행 옆에 표시 |

| 행동 | 노출 방식 | 이유 |
| --- | --- | --- |
| 마지막 입력 되돌리기 | 텍스트 버튼 | 빈도가 낮지만 즉시 찾을 수 있어야 함 |
| 비용 원장 / 매출 기록 | 텍스트 버튼 | 입력 시트와 원장 화면을 이어 주되 큰 카드로 만들지 않음 |
| 아카이브 포함 | 작은 토글 | 기본 시야에는 운영 중인 항목만 남김 |
| 채널 추가 | `＋ 채널` | 채널은 시트 구조를 바꾸는 상위 객체라 시트 머리에서 생성 |
| 삭제 지표 복원 | `⋯ 더보기` | 평소에는 필요한 기능이 아니므로 숨김 |

## 6. 데이터가 늘어날 때의 동작

### 6.1 채널·소재·지표 수 증가

1. 채널 행은 사용자가 정한 순서를 유지한다.
2. 채널을 접으면 대표 지표 선택값과 일별 값만 보인다.
3. 소재는 기본 접힘으로 시작하되, 이번 달에 값이 입력된 소재는 첫 진입 시 한 번 더 쉽게 찾을 수 있어야 한다. 구현 방식은 색상 점 또는 `입력 있음` 수로 검토한다.
4. 소재의 정렬은 이미 적용된 등록 과거순을 유지한다.
5. 아카이브 소재는 기본 숨김을 유지하고, 토글을 켰을 때만 과거 행까지 펼친다.

### 6.2 가로 날짜 증가 및 스크롤

- `운영 대상/지표`, `월간 요약`, 날짜 헤더는 항상 고정한다.
- 화면을 열면 오늘 날짜가 보이는 지점으로 자동 이동한다.
- 오늘 열은 테두리와 아주 옅은 배경으로만 강조한다. 다른 채널 색보다 강해지지 않게 한다.
- 일요일·이벤트·광고 집행 불가 기간의 구분은 현재 의미를 유지하되, 색을 과도하게 겹치지 않는다.

### 6.3 긴 이름과 많은 정보

- 표 안의 이름은 한 줄 말줄임표로 제한한다.
- 전체 이름, 입력 방식, 집계 방식, 광고 집행 기간은 호버 툴팁 또는 상세 모달에서 확인한다.
- 행 안에 설명 문단을 늘리지 않는다. 표는 숫자를 읽는 곳이며 상세 설명은 모달에 둔다.

## 7. 인터랙션 기준

| 대상 | 기본 행동 | 보조 행동 |
| --- | --- | --- |
| 날짜 헤더 | 해당 날짜의 이벤트 기록 열기 | 이벤트가 있으면 점으로 표시 |
| 이벤트 이름 | 이벤트 상세 수정 열기 | 원가를 툴팁으로 확인 |
| 채널/소재/키워드 이름 | 접기·펼치기 | `⋯`에서 수정·아카이브·삭제 |
| 대표 지표 선택 | 채널/소재의 월간·일별 요약 표시 기준 변경 | 선택은 해당 작업공간 브라우저에 기억 |
| 입력 셀 | 숫자 입력, blur 자동 저장 | Enter/Tab/방향키 이동, 범위 붙여넣기, Esc 취소 |
| 계산 셀 | 값과 계산 규칙 확인 | 직접 편집 불가 |
| 열 경계 | 운영 대상/월간 요약 폭 조절 | 키보드 화살표로도 조절 |

## 8. 이번 개편에서 하지 않는 일

- 업무·프로젝트·체크리스트를 대시보드에 다시 표시하거나 생성하지 않는다.
- 현재 집계, 비용 포함 규칙, 순위 표시 규칙, 입력 데이터의 의미를 변경하지 않는다.
- 새 분석 카드나 인과관계를 가정한 채널별 매출 귀속을 추가하지 않는다.
- 채널/소재/지표의 데이터 구조를 바꾸지 않는다. 먼저 화면 계층과 조작 위치만 정리한다.
- 대용량 다중 학원용 가상 스크롤, 권한 체계, 광고 API 자동 수집은 이 단계의 범위가 아니다.

## 9. 구현 단계와 승인 기준

### 1단계: 화면 위계 정리

- L2를 저장 상태·기간·입력 조작으로 정리한다.
- KPI 5개를 컴팩트한 성과 스트립으로 바꾼다.
- 운영 시트의 제목, 행동 영역, 그룹 행·입력 행·계산 행의 시각 위계를 정리한다.
- 기존 입력·저장·집계 결과가 같음을 내부 테스트로 확인한다.

### 2단계: 시트 탐색성 강화

- 채널 접힘 상태와 최근 입력 표시를 다듬는다.
- 대표 지표 선택, 툴팁, 더보기 행동을 정리한다.
- 날짜 스크롤과 오늘 강조의 대비를 점검한다.

### 3단계: 실제 데이터 기반 조정

- 로한이 한 달 실제 데이터를 입력한 상태에서 불필요한 행·버튼·색을 제거한다.
- 필요할 때만 분석 화면으로 이동하는 연결을 추가한다.

### 승인 기준

아래에 동의한 뒤에만 UI 코드를 수정한다.

1. 대시보드의 중심은 별도 카드 묶음이 아니라 가로 날짜 운영 시트다.
2. KPI는 5개 성과 스트립으로 압축하고, ROI·객단가는 분석 화면에서 다룬다.
3. 업무 기능은 대시보드에 넣지 않고 업무 화면에만 둔다.
4. 데이터 구조·계산·현재 입력 방식은 바꾸지 않고, 화면 위계와 조작 위치부터 정리한다.
