# 로한 마케팅 업무·프로젝트 관리 요구사항정의서

문서 상태: 2단계 구현 완료 기준
작성일: 2026-09-21
제품: 로한 마케팅

## 1. 문서 목적

로한 마케팅을 채움영어 풍무캠퍼스의 마케팅 운영시트에서 개인 업무·프로젝트·일정·처리 결과를 함께 추적하는 업무 관리 도구로 확장한다. 사용자는 프로젝트 전체 흐름을 타임라인으로 보고, 오늘 해야 할 일을 투 두 리스트로 확인하며, 원장님이나 다른 선생님에게 받은 업무의 요청자와 마감일을 놓치지 않아야 한다.

행정사 업무 모델은 이번 범위에 포함하지 않는다. 다만 업무·프로젝트·반복 일정 구조는 나중에 다른 업무 영역을 추가할 수 있도록 일반적인 이름과 관계로 설계한다.

## 2. 현재 문제

- 프로젝트가 여러 날짜와 준비 단계에 걸쳐 있어 캘린더만 보면 전체 흐름을 파악하기 어렵다.
- 오늘 해야 할 일, 기한이 지난 일, 반복 업무, 다른 사람이 요청한 일이 한곳에 모여 있지 않다.
- 요청받은 업무는 누가 시켰는지와 언제까지 해야 하는지가 중요하지만 기존 운영시트에는 이를 기록할 위치가 없다.
- 실제 행사·광고·콘텐츠 기록과 준비 업무가 분리되어 있어 업무가 어떤 운영 기록으로 이어졌는지 추적하기 어렵다.
- 기존 구글 캘린더 일정과 앱에서 관리하는 업무가 따로 있어 일정 중복과 누락이 생길 수 있다.

## 3. 제품 범위와 핵심 원칙

### 3.1 핵심 사용자

현재 사용자는 로한 한 명이다. 업무를 요청하는 사람은 원장님, 다른 선생님, 외부 업체 등으로 입력할 수 있다. 초기에는 별도 사용자 계정이나 협업 권한을 만들지 않고, 요청자 이름을 기록하는 방식으로 시작한다.

### 3.2 업무 계층

```text
업무 영역
└─ 프로젝트
   └─ Task
      └─ 메모·상태 변경·처리 결과
```

예시:

```text
채움영어 풍무캠퍼스 마케팅
├─ 29일 풍무중 영어시험날 행사
│  ├─ 행사 물품 구매
│  ├─ 행사 안내물 제작
│  └─ 시험날 현장 준비
├─ 30일 2차 설명회
│  ├─ 신청폼 확인
│  └─ 설명회 자료 최종 점검
├─ 기타 온라인 마케팅 세팅
└─ 버스정류장 광고 세팅
```

### 3.3 운영 원칙

1. Task 하나를 저장하고 오늘 목록, 프로젝트 목록, 타임라인, 캘린더에서 각각 보여준다. 화면마다 별도 일정을 만들지 않는다.
2. 마감일과 실제 실행 예정일을 분리한다. 마감일은 언제까지 끝내야 하는지, 실행일은 언제 작업할 것인지 나타낸다.
3. 내가 만든 업무와 요청받은 업무를 같은 데이터로 관리하되, `업무 출처`와 `요청자`로 빠르게 구분한다.
4. 반복 업무는 매일 또는 매주 실제 완료 여부를 기록할 수 있어야 한다. 캘린더에 모양만 표시되는 가짜 일정으로 처리하지 않는다.
5. 기존 이벤트 페이지는 실제 행사 결과·비용·물품 사용량을 기록하고, Task는 준비·진행·후속 업무를 기록한다. Task에서 이벤트를 연결할 수 있다.
6. 구글 캘린더는 처음부터 모든 내용을 자동 양방향 동기화하지 않는다. 기존 일정은 읽어오고, 사용자가 선택한 Task만 외부 캘린더에 등록하는 방식으로 시작한다.

## 4. 주요 용어

| 용어 | 정의 |
| --- | --- |
| 업무 영역 | 지속적으로 관리하는 큰 업무 묶음. 예: 채움영어 풍무캠퍼스 마케팅 |
| 프로젝트 | 시작과 완료가 있는 목표 단위. 예: 30일 2차 설명회 |
| Task | 실제로 처리해야 하는 한 건의 업무 |
| 반복 업무 | 매일·매주·매월 같은 규칙으로 다시 발생하는 업무 |
| 요청받은 업무 | 원장님이나 다른 선생님 등 외부 요청자로부터 받은 Task |
| 이벤트 | 실제 설명회·행사 결과, 비용, 물품 사용량을 기록하는 기존 기능 |
| 실행 예정일 | 작업을 수행하려는 날짜 또는 시간 |
| 마감일 | 업무를 완료해야 하는 최종 날짜 또는 시간 |

## 5. 사용자 시나리오

### 5.1 오늘 해야 할 일 확인

사용자는 업무 페이지를 열고 오늘 마감, 오늘 실행, 기한 초과, 반복 업무를 한 화면에서 확인한다. 각 항목에는 프로젝트, 요청자, 우선순위, 마감 시간이 표시된다.

### 5.2 요청받은 업무 등록

원장님이 “29일 행사 준비를 이번 주 안에 끝내 달라”고 요청하면 사용자는 빠른 입력창에서 제목, 요청자, 마감일만 먼저 등록한다. 이후 프로젝트, 실행 예정일, 메모, 결과를 보완한다.

### 5.3 프로젝트 전체 흐름 확인

사용자는 `30일 2차 설명회` 프로젝트를 열어 준비 Task와 후속 Task를 시간순으로 확인한다. 프로젝트 타임라인에는 프로젝트 기간과 주요 마일스톤이 표시된다.

### 5.4 반복 업무 처리

사용자는 `매일 광고 지표 입력`을 반복 업무로 등록한다. 오늘 발생한 업무를 완료하면 오늘 회차만 완료 처리되고, 다음 발생일의 업무는 다시 열린 상태로 남는다.

### 5.5 기존 운영 기록과 연결

사용자는 `29일 풍무중 영어시험날 행사` 준비 Task를 기존 이벤트 기록에 연결한다. 이벤트 페이지에서 실제 비용과 물품 사용량을 기록한 뒤, Task에는 처리 결과와 후속 조치를 남긴다.

### 5.6 구글 캘린더 사용

사용자는 날짜와 시간이 있는 Task에서 `구글 캘린더에 등록`을 누른다. 기존 구글 일정은 앱 캘린더에 읽기 전용으로 표시되고, 앱에서 만든 Task와 구분된다.

## 6. 기능 요구사항

### 6.1 업무 영역과 프로젝트

- FR-001: 업무 영역을 만들고 이름·설명·색상을 수정할 수 있어야 한다.
- FR-002: 프로젝트를 업무 영역 아래에 만들고 시작일·목표일·상태를 기록할 수 있어야 한다.
- FR-003: 프로젝트를 진행 중·완료·보류 상태로 구분할 수 있어야 한다.
- FR-004: 프로젝트 목록은 진행 중인 항목을 위에 두고, 사용자가 순서를 조정할 수 있어야 한다.
- FR-005: 프로젝트를 기존 이벤트·채널·콘텐츠와 연결할 수 있어야 한다. 연결은 기존 마케팅 데이터나 비용을 자동으로 변경하지 않는다.

### 6.2 Task 등록과 편집

- FR-010: Task 제목, 프로젝트, 상태, 우선순위, 실행 예정일, 마감일을 저장할 수 있어야 한다.
- FR-011: Task에 메모, 처리 결과, 다음 행동을 기록할 수 있어야 한다.
- FR-012: Task의 업무 출처를 `내가 만든 업무`, `요청받은 업무`, `반복 업무` 중 하나로 선택할 수 있어야 한다.
- FR-013: 요청받은 업무에는 요청자, 요청일, 요청 내용을 기록할 수 있어야 한다.
- FR-014: 요청자 이름은 원장님, 선생님, 외부 업체 등 자유 입력이 가능해야 한다. 동일 요청자 관리가 필요해지면 이후 요청자 목록으로 승격한다.
- FR-015: 마감일만 있는 Task와 실행 예정일이 있는 Task를 구분해 표시해야 한다.
- FR-016: 완료 처리 시 완료일을 저장하고, 처리 결과가 비어 있으면 결과 입력을 유도해야 한다.
- FR-017: 삭제는 휴지통 또는 보관 방식으로 처리해 업무 이력을 보존해야 한다.

### 6.3 상태·우선순위·정렬

- FR-020: 상태는 `받은 요청`, `예정`, `진행 중`, `대기`, `보류`, `완료`, `취소`를 지원한다.
- FR-021: 대기 상태에는 대기 사유나 다음 확인일을 기록할 수 있어야 한다.
- FR-022: 우선순위는 높음·보통·낮음으로 구분한다.
- FR-023: 오늘 화면은 마감 초과, 오늘 마감, 오늘 실행, 우선순위 순으로 정렬한다.
- FR-024: 사용자는 프로젝트와 Task의 순서를 드래그 또는 위·아래 버튼으로 조정할 수 있어야 한다.

### 6.4 반복 업무

- FR-030: 매일·매주·매월 반복 규칙을 등록할 수 있어야 한다.
- FR-031: 반복 업무는 발생 회차마다 완료 여부를 별도로 기록해야 한다.
- FR-032: 반복 업무의 다음 발생일을 자동 계산해야 한다.
- FR-033: 특정 회차를 건너뛰거나 일회성으로 완료할 수 있어야 한다.
- FR-034: 반복 규칙을 중지해도 과거 완료 기록은 보존해야 한다.

### 6.5 화면과 보기

- FR-040: `업무` 메뉴를 추가하고 오늘·전체·프로젝트·요청받은 업무·반복 업무 필터를 제공해야 한다.
- FR-041: 오늘 화면은 오늘 해야 할 일을 가장 먼저 보여주고, 기한 초과 항목을 별도 강조해야 한다.
- FR-042: 타임라인 화면은 프로젝트 기간과 하위 Task의 실행 예정일·마감일을 함께 보여줘야 한다.
- FR-043: 캘린더 화면은 실행 예정일, 마감일, 반복 업무와 구글 일정 오버레이를 구분해야 한다.
- FR-044: 프로젝트 상세 화면에서 Task, 메모, 처리 결과, 연결된 이벤트를 한 번에 확인할 수 있어야 한다.
- FR-045: 작은 화면에서도 기존 운영시트처럼 과도한 상하 여백 없이 컴팩트하게 동작해야 한다.

### 6.6 구글 캘린더 연동

- FR-050: 사용자가 구글 계정을 연결하고 캘린더 선택 권한을 승인할 수 있어야 한다.
- FR-051: 기존 구글 일정은 앱 캘린더에 읽기 전용으로 표시해야 한다.
- FR-052: 사용자가 선택한 Task를 구글 캘린더에 등록할 수 있어야 한다.
- FR-053: 실행 예정일과 시간이 있으면 해당 시간의 일정으로 만들고, 날짜만 있으면 종일 일정으로 만든다.
- FR-054: 마감일만 있는 Task는 기본적으로 캘린더에 자동 생성하지 않고, 사용자가 등록할 때 선택하게 한다.
- FR-055: 한 Task가 여러 번 등록되지 않도록 앱의 Task ID와 구글 이벤트 ID를 연결해 저장해야 한다.
- FR-056: 초기 버전에서는 외부 구글 일정을 자동으로 Task로 변환하지 않는다. 사용자가 선택한 일정만 Task로 가져온다.
- FR-057: 이후 양방향 동기화를 도입할 때는 충돌 정책과 연결 해제 기능을 별도로 정의한다.

## 8. 데이터 구조 초안

초기 Supabase 테이블은 기존 마케팅 테이블과 분리된 `mkt_` 업무 테이블로 둔다.

### 8.1 `mkt_work_areas`

- `id`, `workspace_id`, `name`, `description`, `color`, `sort_order`, `archived_at`, `created_at`, `updated_at`

### 8.2 `mkt_work_projects`

- `id`, `workspace_id`, `area_id`, `name`, `description`
- `status`, `priority`, `start_at`, `due_at`, `sort_order`
- 기존 기록 연결용 `linked_entity_type`, `linked_entity_id`
- `archived_at`, `created_at`, `updated_at`

### 8.3 `mkt_tasks`

- `id`, `workspace_id`, `area_id`, `project_id`
- `title`, `description`, `result`, `next_action`
- `source_type` (`self`, `requested`, `recurring`)
- `requester_name`, `requested_at`, `request_note`
- `status`, `priority`, `start_at`, `due_at`, `remind_at`
- `completed_at`, `sort_order`, `deleted_at`, `created_at`, `updated_at`
- 기존 이벤트·콘텐츠·채널 연결용 `linked_entity_type`, `linked_entity_id`

### 8.4 `mkt_task_recurrences`

- `id`, `workspace_id`, `task_template_id`
- `frequency`, `interval`, `weekday`, `day_of_month`
- `starts_on`, `ends_on`, `next_occurrence_on`, `active`

### 8.5 `mkt_task_occurrences`

- `id`, `workspace_id`, `recurrence_id`, `task_id`
- `occurrence_on`, `status`, `completed_at`, `result`, `skipped_at`

반복 업무는 원본 규칙과 실제 발생 회차를 분리한다. 그래야 `매일 광고 지표 입력`의 오늘 완료 여부와 과거 완료 이력을 함께 보존할 수 있다.

### 8.6 구글 캘린더 연결

- `mkt_calendar_connections`: 연결된 구글 계정·캘린더·동기화 상태
- `mkt_task_calendar_links`: Task ID, 구글 캘린더 ID, 구글 이벤트 ID, 마지막 동기화 시각, 동기화 상태

구글 OAuth 토큰은 브라우저나 일반 업무 데이터에 저장하지 않고 서버 측 보안 저장소에서 관리한다.

## 9. 상태 전이와 알림 기준

```text
받은 요청 → 예정 → 진행 중 → 완료
                    ├→ 대기 → 진행 중
                    ├→ 보류 → 예정 또는 진행 중
                    └→ 취소
```

- 마감일이 지나고 완료되지 않은 Task는 `기한 초과`로 표시한다. 상태를 자동으로 완료나 취소로 바꾸지 않는다.
- 알림은 앱 내부 알림을 먼저 제공하고, 구글 캘린더 등록을 선택한 Task는 구글 캘린더 알림을 사용한다.
- 알림 기능이 구현되기 전에도 마감일과 오늘 목록은 정상적으로 표시되어야 한다.

## 13. UI/UX 기획

### 13.1 화면 역할 재정의

현재 대시보드는 마케팅 수치와 날짜별 운영 입력을 처리하는 화면이다. 업무 기능을 추가해도 대시보드를 프로젝트 상세 화면으로 바꾸지 않는다. 대시보드는 다음 세 가지를 빠르게 확인하는 운영 홈으로 유지한다.

1. 오늘 어떤 프로젝트 활동을 처리해야 하는가
2. 선택한 기간의 학원 퍼널·비용·매출이 어떻게 움직이는가
3. 날짜별 운영시트에 어떤 지표를 입력해야 하는가

프로젝트의 세부 업무, 메모, 처리 결과, 연결 기록은 업무 페이지의 프로젝트 상세에서 관리한다. 대시보드는 프로젝트로 들어가는 짧은 진입점만 제공한다.

### 13.2 메뉴와 정보 구조

기존 메뉴의 순서는 유지하되 `업무`를 대시보드 다음에 추가한다.

```text
대시보드 → 업무 → 콘텐츠 → 이벤트 → 구매 → 분석 → 리포트 → 로그
```

`업무` 메뉴의 기본 진입 화면은 `오늘`이다. 사용자가 마지막으로 보던 프로젝트·보기·필터를 브라우저 뒤로가기와 함께 보존한다.

업무 페이지 안에서는 상단 필터와 보기 전환을 분리한다.

```text
[오늘 5] [프로젝트] [전체] [요청받은 업무] [반복 업무]
[목록] [타임라인] [캘린더]
```

상단 필터는 무엇을 볼지 결정하고, 목록·타임라인·캘린더는 같은 데이터를 어떻게 볼지 결정한다. 필터를 바꿔도 날짜와 프로젝트 선택은 불필요하게 초기화하지 않는다.

### 13.3 대시보드 레이아웃

현재 컴팩트한 가로 운영시트의 밀도와 입력 흐름을 유지하면서 다음 순서로 배치한다.

```text
상단 바·기간 선택
↓
오늘의 프로젝트 활동
↓
학원 퍼널·마케팅 비용·매출 KPI
↓
날짜별 운영시트
↓
진행 중 프로젝트 요약
```

#### 오늘의 프로젝트 활동

대시보드 첫 영역에는 오늘 실행할 Task와 기한 초과 Task를 가로 스크롤 가능한 컴팩트 행으로 표시한다.

```text
오늘의 프로젝트 활동  [업무 페이지 열기]

[기한 초과 1]  설명회 신청폼 최종 확인 · 30일 2차 설명회 · 원장님
[오늘 2]       광고 지표 입력 · 온라인 마케팅 세팅
[오늘 1]       행사 물품 수량 확인 · 29일 행사
```

- Task마다 완료 체크, 제목, 프로젝트, 요청자 또는 반복 표시, 마감 시각을 보여준다.
- 기한 초과는 짧은 색상 강조로 표시하고 카드 높이를 키우지 않는다.
- 완료한 Task는 기본적으로 숨기고 `완료 포함`을 선택했을 때만 펼친다.
- Task 제목을 누르면 업무 상세로 이동한다.
- `업무 페이지 열기`는 현재 필터를 유지한 채 오늘 목록으로 이동한다.
- Task가 없으면 빈 카드 대신 `오늘 등록된 프로젝트 활동이 없습니다`와 `＋ 업무 추가`만 표시한다.

#### 기존 KPI와 운영시트

KPI와 운영시트는 기존 위치와 계산 계약을 유지한다. Task 완료 여부나 프로젝트 상태가 마케팅 비용·유입·상담·등록·매출 계산에 자동으로 더해지지 않는다. 수치가 발생하는 기록은 기존 이벤트·구매·비용·지표 입력에서만 만든다.

운영시트의 날짜 헤더에는 해당 날짜의 Task 수를 작은 점 또는 숫자로 표시한다. 날짜를 누르면 기존 이벤트 입력 동작을 잃지 않도록 `날짜 활동 패널`을 연다.

```text
9/29  ●3
      ├─ Task 2건
      ├─ 이벤트 1건
      └─ [업무 추가] [이벤트 기록]
```

날짜 활동 패널에서 Task를 완료하거나 이벤트를 기록할 수 있다. 기존 운영시트의 셀 입력은 패널을 닫은 뒤에도 그대로 이어진다.

#### 진행 중 프로젝트 요약

운영시트 아래에는 진행 중인 프로젝트를 한 줄 카드로 표시한다.

- 프로젝트명
- 시작일·목표일
- 미완료 Task 수
- 다음 마감 Task
- 연결된 이벤트·채널·콘텐츠가 있으면 작은 연결 배지

프로젝트 카드의 성과 수치 전체를 대시보드에 복제하지 않는다. `상세 보기`를 누르면 업무 페이지의 프로젝트 상세로 이동하고 그곳에서 연결된 운영 기록과 비용·성과를 확인한다.

### 13.4 프로젝트 상세 화면

프로젝트 상세는 프로젝트의 계획과 실제 운영 활동을 한 화면에서 연결하는 화면이다.

```text
← 업무

30일 2차 설명회        진행 중       9/30
미완료 3 · 다음 마감 9/28 · [구글 캘린더]

[업무] [운영 기록] [비용·성과] [활동 로그]
```

- `업무`: Task 목록, 상태·우선순위·요청자·마감일, 메모와 결과
- `운영 기록`: 연결된 이벤트·콘텐츠·채널·구매 기록으로 이동하는 목록
- `비용·성과`: 기존 분석 계산에서 읽은 기간 비용·유입·상담·등록·매출 요약. 이 화면에서 수치를 직접 수정하지 않는다.
- `활동 로그`: Task 상태 변경, 결과 기록, 연결·해제 이력을 시간순으로 표시

프로젝트 상세의 기본 탭은 `업무`로 한다. 운영 기록과 비용·성과는 필요할 때 펼쳐 확인하는 구조로 만들어 상하 공간을 줄인다.

### 13.5 활동 연결 규칙

마케팅 대시보드의 기존 항목은 프로젝트 안에서 발생한 활동으로 연결할 수 있지만, 기존 기록을 Task로 복사하지 않는다.

```text
프로젝트
├─ Task: 인스타 광고 세팅
├─ 연결 이벤트: 30일 2차 설명회
├─ 연결 채널: 인스타그램
├─ 연결 콘텐츠: 설명회 홍보 카드뉴스
└─ 연결 구매: 설명회 리플렛
```

- Task는 사람이 해야 할 행동과 결과를 기록한다.
- 이벤트는 실제 행사 사실과 비용·물품 사용량을 기록한다.
- 채널·콘텐츠·광고 집행은 날짜별 성과 지표와 비용을 기록한다.
- 구매는 결제액·수량·사용량을 기록한다.
- 연결은 조회 경로를 만들 뿐, 원본 기록의 금액·지표를 복제하거나 재합산하지 않는다.

프로젝트에 연결된 원본 기록에는 `프로젝트 연결됨` 배지를 표시하고, 배지를 누르면 해당 프로젝트로 돌아온다. 연결 관계는 양쪽에서 해제할 수 있다.

### 13.6 Task 카드와 목록 밀도

Task 한 줄에 다음 정보를 우선순위 순으로 보여준다.

```text
[완료] 제목 · 프로젝트 · 요청자/반복 · 마감
```

- 제목은 가장 먼저 보여주고 두 줄을 넘기지 않는다.
- 프로젝트명은 작은 보조 텍스트로 표시한다.
- 요청자와 반복 여부는 작은 배지로 표시한다.
- 마감은 `오늘`, `내일`, `9/28`, `기한 초과`처럼 짧게 표시한다.
- 메모·결과·다음 행동은 펼친 상세에서만 보여준다.
- 모바일 또는 좁은 화면에서는 프로젝트와 요청자를 다음 줄로 내리고, 조작 버튼은 아이콘 중심으로 표시한다.

상태 색상은 의미를 고정한다.

| 상태 | 표현 |
| --- | --- |
| 받은 요청 | 보라색 점 + `요청` 배지 |
| 진행 중 | 파란색 점 |
| 대기 | 주황색 점 |
| 기한 초과 | 빨간색 마감 텍스트 |
| 완료 | 낮은 대비의 취소선·회색 |

색상만으로 상태를 전달하지 않고 텍스트와 아이콘을 함께 제공한다.

### 13.7 캘린더와 타임라인 UX

- 타임라인의 가로축은 날짜이며, 프로젝트 바는 시작일·목표일을 기준으로 표시한다.
- Task는 실행 예정일과 마감일이 모두 있으면 막대, 하나만 있으면 점 또는 짧은 막대로 표시한다.
- 오늘 날짜는 기존 운영시트와 동일하게 서버 기준 한국 날짜로 강조한다.
- 날짜 헤더를 누르면 해당 날짜 활동 패널을 열고, Task·이벤트·구글 일정 오버레이를 함께 확인한다.
- 구글 일정은 외부 일정 색상과 `Google` 배지로 구분한다.
- 일정이 없는 Task는 타임라인에 억지로 넣지 않고 `날짜 미정` 목록에 둔다.

### 13.8 구글 캘린더 연동 위치

구글 캘린더 연결은 업무 페이지의 캘린더 보기 상단 설정에서 관리한다.

```text
캘린더
[앱 일정] [구글 일정 표시] [캘린더 연결]
```

Task 상세와 날짜 활동 패널에는 `구글 캘린더에 등록` 버튼을 둔다. 사용자가 선택한 Task만 등록하며, 이미 등록된 Task는 `캘린더에서 열기`와 `연결 해제`를 보여준다.

대시보드에는 구글 캘린더 일정을 직접 편집하는 컨트롤을 넣지 않는다. 대시보드는 확인과 업무 진입에 집중하고, 연결·동기화 설정은 업무 캘린더에서 처리한다.

### 13.9 대시보드와 프로젝트 간 연결 기준

| 대시보드에서 보이는 것 | 클릭 시 이동 | 원본 데이터 |
| --- | --- | --- |
| 오늘의 프로젝트 활동 Task | Task 상세 또는 오늘 업무 | `mkt_tasks` |
| 날짜의 Task 수 | 날짜 활동 패널 | `mkt_tasks` |
| 진행 중 프로젝트 카드 | 프로젝트 상세 | `mkt_work_projects` |
| 운영시트 지표 셀 | 기존 운영시트 입력 | `mkt_values` |
| 비용 원장 버튼 | 분석·비용 탭 | `mkt_costs`, 구매 결제 |
| 이벤트 날짜 | 이벤트 상세 또는 날짜 활동 패널 | `marketing_events` |
| 연결된 채널·소재 배지 | 콘텐츠·운영시트 | 기존 채널·콘텐츠·집행 |

대시보드에 같은 Task나 비용을 두 번 표시하지 않는다. 프로젝트 활동 요약은 실행해야 할 일의 안내이고, KPI·운영시트는 실제 기록과 계산의 기준이다.

### 13.10 프로젝트 범위와 수치 계산

대시보드의 기본 범위는 기존처럼 학원 전체 마케팅이다. 프로젝트를 선택하면 업무와 연결 기록을 좁혀 볼 수 있지만, 프로젝트를 선택했다는 이유만으로 공통 채널·지표·비용을 자동으로 프로젝트별 배분하지 않는다.

- 프로젝트에 직접 연결된 이벤트·구매·비용·콘텐츠·집행만 프로젝트 활동 목록에 표시한다.
- 프로젝트에 연결되지 않은 공통 채널이나 비용은 `미배정 활동`으로 남긴다.
- 프로젝트별 비용·ROI를 표시할 때는 직접 연결된 금액만 계산하고, 공통 비용은 별도 표시한다.
- 학원 전체 KPI는 프로젝트 필터를 열어도 기존 전체 계산을 유지한다.
- 향후 프로젝트별 성과를 계산하려면 원본 기록에 명시적인 프로젝트 연결을 저장한 뒤 별도 집계 규칙을 추가한다.

이 규칙으로 프로젝트 화면은 업무와 운영 기록을 긴밀하게 연결하면서도, 기존 마케팅 비용·ROI 계산을 임의로 바꾸지 않는다.

## 14. UI/UX 수용 기준

- 대시보드 첫 화면에서 오늘의 Task와 기한 초과 Task를 별도 메뉴로 이동하지 않고 확인할 수 있다.
- 오늘의 Task 제목을 누르면 업무 상세로 이동하고, 완료 체크는 대시보드에서도 저장된다.
- 운영시트 날짜 헤더에서 Task 수와 이벤트 존재 여부를 구분해 확인할 수 있다.
- 기존 날짜 클릭의 이벤트 기록 기능과 운영시트 셀 입력 흐름이 유지된다.
- 프로젝트 상세에서 Task와 연결된 이벤트·채널·콘텐츠·구매 기록을 원본으로 이동할 수 있다.
- 프로젝트의 비용·성과 요약은 기존 분석 계산과 같은 값을 보여주며, Task 상태 때문에 비용이나 매출이 변하지 않는다.
- 업무 페이지의 필터·보기·프로젝트 선택은 브라우저 뒤로가기와 함께 복원된다.
- 구글 캘린더 일정과 앱 Task가 색상·배지로 구분되고, 선택한 Task만 외부 캘린더에 등록된다.
- 기존 운영시트의 컴팩트한 높이와 가로 날짜 구조를 훼손하지 않는다.
