# 채움 마케팅 운영 UI 설계서

## 1. 설계 한 줄

**한 달의 마케팅 운영을 한 장의 스프레드시트처럼 입력하고, 콘텐츠·광고·이벤트의 접점을 상담·등록·매출까지 연결해 효율을 판단한다.**

이 서비스의 주 사용자는 한 명의 마케팅 담당자다. 따라서 보기 좋은 대시보드보다 `빠르게 정확히 기록하는 경험`을 우선한다. 단, 대표 보고와 향후 SaaS 통합을 고려해 데이터의 출처·기간·집계 방법은 항상 남긴다.

마케팅의 최종 산출은 노출이나 클릭이 아니라 매출이다. 따라서 이 서비스는 아래 세 질문에 답할 수 있어야 한다.

1. 어떤 활동이 실제 상담·등록·매출의 **접점**이 되었는가?
2. 그 활동에 얼마를 쓰고, 상담·등록 한 건과 매출 1원당 얼마를 썼는가?
3. 이번 달의 결과는 단순한 동시 발생인지, 확인 가능한 근거가 있는 기여인지?

## 2. 정보 구조

| 상단 메뉴 | 역할 | 기본 화면과의 관계 |
|---|---|---|
| 운영 | 월간 입력과 당일 확인 | **기본 진입 화면** |
| 콘텐츠 | 콘텐츠 자산 등록·상태·개별 성과 확인 | 운영 화면의 콘텐츠 행과 연결 |
| 이벤트 | 설명회·커피차·방송 출연 등 일회성 사건 관리 | 운영 화면의 이벤트 행과 연결 |
| 비용 | 광고·제작·굿즈·이벤트 비용 원장 | 운영 화면의 비용과 연결 |
| 분석 | 접점·전환·매출·효율 분석 | 수기 입력을 의사결정으로 전환 |
| 채널 설정 | 채널 CRUD, 측정 프로필, 표시 순서 | 설정 드로어 또는 별도 관리 화면 |
| 리포트 | 기간 요약, PDF, Excel | 상단 메뉴의 드롭다운 |

`대시보드`라는 모호한 메뉴는 만들지 않는다. 매일 입력하는 수치는 `운영`, 매출까지 해석하는 화면은 목적이 분명한 `분석`으로 둔다.

## 3. 공통 SaaS 프레임

### 상단 바

```
[C] 채움 마케팅 / 풍무캠퍼스     운영   콘텐츠   이벤트   비용   분석   채널 설정   리포트⌄     검색   동기화됨   BH⌄
```

- 좌측은 서비스 정체성과 캠퍼스. 다른 브랜드·캠퍼스가 생길 때 이 영역이 전환 메뉴가 된다.
- 중앙은 실제 업무 단위 메뉴만 둔다. 보고서 버튼을 화면 본문에 흩어놓지 않는다.
- 우측은 검색, 저장 상태, 계정 메뉴로 통일한다.
- 현재 메뉴는 초록색 하단선으로 표시한다. 상단 바는 항상 고정한다.

### 화면 언어와 시각 규칙

- 기본 바탕: 아주 옅은 회색, 작업 영역: 흰색 카드. 색은 데이터 의미에만 쓴다.
- 브랜드 초록: 주요 행동·정상 저장·긍정 상태.
- 주황: 비용·주의. 빨강은 오류·마감 임박에만 사용한다.
- 숫자는 오른쪽 정렬, 한글 레이블은 왼쪽 정렬, 모든 금액은 `38,560원`으로 통일한다.
- 빈 값은 `—`, 실제 0은 `0`으로 보인다. 둘을 절대 같은 의미로 쓰지 않는다.
- 아이콘만 있는 버튼은 툴팁을 제공하고, 기본 행동은 텍스트를 함께 보여 준다.

### 반드시 지킬 입력 규칙

1. **날짜는 위, 대상·지표는 왼쪽.** 가로 스크롤을 해도 좌측 두 열(행 이름·월 합계)은 고정한다.
2. **한 셀은 한 수치.** `노출/클릭/지출`을 하나의 카드 안에 섞지 않는다. 바로 타이핑하거나 클릭 후 숫자를 입력한다.
3. **상담·등록은 학원 전체 퍼널에만 있다.** 채널이나 콘텐츠 행에는 넣지 않는다.
4. **채널은 컨테이너, 콘텐츠/광고 소재는 하위 자산, 이벤트는 독립 블록이다.** 동일한 모습으로 보이더라도 데이터 성격은 섞지 않는다.
5. **월 합계는 지표별 집계법을 따른다.** 당근 일 지출은 합계, 인스타 누적 조회수는 가장 마지막(최대) 값이다.
6. 행에 마우스를 올리면 `…`가 나타나 콘텐츠 수정·복제·비활성화·삭제를 제공한다. 삭제는 소프트 삭제다.

### 입력 상호작용

- 빈 셀을 클릭하거나 숫자를 입력하면 그 자리에서 편집 가능한 input이 된다.
- `Enter`: 저장 후 아래 행, `Tab`: 오른쪽 날짜, `Shift + Tab`: 왼쪽 날짜로 이동한다.
- 숫자를 지우고 저장하면 미입력(`—`)으로 되돌아간다. `0`을 입력한 경우만 실제 0이다.
- 자동 저장은 입력 후 500ms에 실행하고, 표 상단에 `저장 중… / 자동 저장됨 / 저장 실패`를 표시한다.
- 상세 메모, URL, 집계 기간처럼 숫자 외 정보는 셀의 작은 점 표시를 클릭해 우측 검사 패널에서 편집한다. 이 패널은 수기 숫자 입력을 방해하지 않는다.
- 여러 칸 붙여넣기(CSV/Excel 복사)는 2차 기능으로 추가한다. 첫 버전은 정확한 한 칸 입력과 키보드 이동을 완성한다.

### 블록 별 역할

| 블록 | 입력 행 | 월간 집계 | 목표 |
|---|---|---|---|
| 학원 전체 퍼널 | 유입, 카카오·전화·방문 상담, 등록 | 합계 | 학원 실전환 파악 |
| 유료 광고 | 광고 소재 × 노출/클릭/반응/지출 | 합계 | 광고 효율 비교 |
| 콘텐츠 | 게시물 × 플랫폼 원본 지표 | 합계 또는 최대값 | 어떤 콘텐츠가 반응을 만드는지 확인 |
| 이벤트·오프라인 | 사건 × 신청/참석/현장문의/직접비 | 합계 | DA·SA와 다른 활동의 결과 기록 |
| 비용 | 제작·굿즈·대행 등 비용 항목 | 합계 | 집행액의 실제 원장 관리 |

## 5. 지표를 보여주는 방식

### 당근 광고: 소재를 펼친 뒤 지표를 입력

```
당근 광고  [채널 합계]   클릭률 1.00%  ·  반응당 지출 6,427원
  ├─ 중고등부 오픈 설명회 [광고중]
  │    노출수 / 클릭수 / 반응수 / 지출
  └─ 사용자 동네 성공전략 [광고중]
       노출수 / 클릭수 / 반응수 / 지출
```

`클릭률`, `반응률`, `클릭당 비용`, `반응당 비용`은 옅은 회색의 계산 행 또는 채널 요약 팝오버에만 보여 준다. 직접 입력하지 못하게 한다.

### 인스타그램: 게시물의 누적 스냅샷을 기록

```
인스타그램
  └─ 고입 설명회 릴스 [발행 9/4]
       조회수 / 도달 / 좋아요 / 댓글 / 저장 / 공유 / 프로필 방문 / 링크 클릭
```

인스타 지표는 발행 뒤 각 날짜에 다시 확인할 수 있는 누적값이다. 따라서 월 합계 열은 모든 일자를 더하지 않고, 마지막으로 기록된 값(기본은 최대값)을 보여 준다. 게시물 반응과 참여율은 자동 계산한다.

### 블로그: 게시글 단위의 성과와 검색 맥락

```
네이버 블로그
  └─ 풍무 중3 고입 영어 공략 [발행 9/2]
       조회수 / 검색노출 / 공감 / 댓글 / 상담 링크 클릭
```

블로그는 채널 설정에서 `일별 발생값` 또는 `누적 스냅샷` 중 하나를 선택한다. 기존 엑셀 운영 방식은 조회수 합계를 사용했으므로, 초기 기본값은 합계다.

## 6. 우측 검사 패널: 관리 정보만 다룬다

표를 떠나지 않고 선택한 대상의 설명을 볼 수 있는 패널이다. 숫자 입력의 주 경로가 아니다.

| 선택 대상 | 패널 정보 |
|---|---|
| 콘텐츠 | 제목, 유형(피드/릴스/게시글), 발행일, URL, 키워드, 제작 담당, 제작비, 메모 |
| 광고 소재 | 제목, 광고 상태, 랜딩 URL, 소재 이미지, 시작·종료일, 일 예산, 메모 |
| 이벤트 | 사건명, 일정·장소, 담당자, 대상, 상태, 비용 항목, 결과 메모 |
| 날짜/퍼널 | 유입 출처 메모, 카카오·전화·방문 상담 분해, 특이사항 |

패널은 화면 우측 400px 내외로 열리고, 닫아도 표의 스크롤 위치와 편집 상태가 유지된다.

## 7. 전환·매출 연결 설계

### 세 개의 층을 절대 섞지 않는다

| 층 | 무엇을 기록하는가 | 대표 지표 | 진실의 기준 |
|---|---|---|---|
| 활동 | 광고, 콘텐츠, 이벤트와 비용 | 노출, 클릭, 반응, 지출 | 플랫폼 화면·영수증 |
| 전체 전환 | 학원에서 실제 발생한 일일 결과 | 유입, 카카오·전화·방문 상담, 등록 | 학원 일일 집계 |
| 전환 근거 | 특정 상담·등록이 거친 알려진 접점 | 유입 경로, 첫 접점, 마지막 접점, 보조 접점, 등록 매출 | 상담 시 확인한 응답·현장 기록 |

운영 시트에서는 두 번째 층을 빠르게 입력한다. 특정 채널의 매출 효율을 말해야 하는 순간에만 세 번째 층의 근거를 추가한다. 이 방식이면 매일 입력은 가볍고, 분석은 정직해진다.

### 전환 기록 카드

상담 또는 등록이 발생하면 `전환 기록`을 선택적으로 남긴다. 개인 이름·전화번호는 저장하지 않고, `상담 9/8-03`처럼 내부 참조 번호만 사용한다.

```
상담 9/8-03
상태: 상담 완료 → 등록 완료
알게 된 경로(고객 답변): 인스타그램 릴스
첫 접점: 인스타그램 / 고입 설명회 릴스
보조 접점: 당근 광고 / 중고등부 오픈 설명회, 9월 고입 설명회
등록일: 9/12
등록 매출: 420,000원   [실매출 / 예상매출]
신뢰도: 고객이 직접 답변함 / 운영자 추정 / 미확인
메모: “릴스를 보고 설명회 신청 후 방문”
```

- `알게 된 경로`는 고객에게 직접 물어 확인한 단일 응답이다. 가장 신뢰도 높은 출처로 별도 보관한다.
- `첫 접점`, `마지막 접점`, `보조 접점`은 여러 개를 연결할 수 있다. 콘텐츠·광고 소재·이벤트를 모두 선택 가능하다.
- 모르는 경우는 반드시 `미확인`으로 남긴다. 편의를 위해 임의 채널을 기본값으로 채우지 않는다.
- 상담 일일 합계와 전환 기록의 수는 일치하지 않을 수 있다. 전자는 전체 운영 수치, 후자는 출처까지 확보된 표본이다. 분석 화면에 `출처 확인률`을 함께 표시한다.

### 등록 매출의 정의

학원의 유지·퇴원 관리는 다른 시스템의 범위이므로, 이 서비스에서는 등록과 직접 연결되는 매출만 다룬다.

- 기본 이름: `등록 매출`
- 기본 입력: 실제로 결제된 등록 관련 금액(등록비 + 첫 결제 등, 학원 내부 기준에 따라 설정)
- 선택 입력: 계약·예상 금액. 실매출과 혼동되지 않도록 항상 구분 표기한다.
- 환불이나 정정이 발생하면 기존 기록을 지우지 않고 조정 금액과 사유를 추가한다.

### 비용 연결

비용은 발생한 활동에 직접 연결한다.

- 당근 일 지출 → 해당 광고 소재
- 릴스 외주·촬영비 → 해당 콘텐츠 또는 콘텐츠 묶음
- 설명회 대관·다과·커피차 → 해당 이벤트
- 공용 디자인·월 구독료처럼 어느 하나에만 귀속할 수 없는 비용 → `공용 비용`으로 남기고 채널 효율 계산에서 포함/제외를 토글한다.

따라서 같은 `총 지출`이라도 “광고 소재 비용”, “콘텐츠 제작비”, “이벤트 직접비”, “공용 비용”으로 나누어 본다.

### 효율 지표의 신뢰도 표기

| 지표 | 계산 | 표시 조건 |
|---|---|---|
| 상담당 비용 | 활동 직접비 ÷ 확인된 상담 수 | 출처 확인 상담이 1건 이상일 때 |
| 등록당 비용(CAC) | 활동 직접비 ÷ 확인된 등록 수 | 확인된 등록이 1건 이상일 때 |
| 매출 대비 광고수익(ROAS) | 확인된 실등록 매출 ÷ 직접비 | 실매출이 입력된 전환만 사용 |
| 순효율 | 확인된 실등록 매출 − 직접비 | 공용 비용 포함 여부를 명확히 표시 |
| 출처 확인률 | 접점이 확인된 상담/등록 ÷ 전체 상담/등록 | 모든 분석 화면에 항상 표시 |

`추정 효율`과 `확인 효율`은 같은 카드에 섞지 않는다. 예를 들어 “설명회 다음 주 등록이 늘었다”는 상관관계로 표시할 수는 있어도, 고객 접점 근거가 없으면 설명회 매출로 확정하지 않는다.

## 8. 분석 화면: 입력의 목적을 보여 주는 곳

분석은 별도의 화려한 대시보드가 아니라, 운영 시트에서 쌓인 기록을 판단으로 바꾸는 화면이다.

### 분석 화면의 첫 줄

```
[기간 2026.09.01–09.30] [실매출 기준 ▾] [공용 비용 제외 ▾]

총 직접비 385,600원 | 확인된 등록 매출 1,260,000원 | ROAS 3.27 | CAC 96,400원 | 출처 확인률 62.5%
```

### 아래 네 영역

1. **전환 퍼널** — 유입 → 상담 → 등록 → 실등록 매출. 상담은 카카오·전화·방문으로 분해한다.
2. **활동별 효율 표** — 채널 > 콘텐츠/광고 소재/이벤트를 펼쳐 직접비, 확인 상담, 확인 등록, 확인 매출, CAC, ROAS, 출처 확인률을 비교한다.
3. **접점 흐름** — 고객 답변 기준의 알게 된 경로와 실제 첫/마지막/보조 접점을 나란히 표시한다. 한 등록이 여러 접점을 거쳤다면 ‘보조 기여’로만 보이며 매출을 중복 합산하지 않는다.
4. **시점 비교** — 광고 집행·콘텐츠 발행·이벤트 일정 위에 일일 상담/등록 추이를 겹친다. 이 영역은 `상관관계`라고 명시한다.

### 매출 귀속 보기 방식

보고서에서 사용자가 선택할 수 있지만, 각 방식의 결과를 동시에 더하지 않는다.

| 보기 방식 | 용도 | 원칙 |
|---|---|---|
| 고객 응답 기준 | “어디서 알게 되었나” 판단 | 고객이 답한 하나의 경로에만 매출을 연결 |
| 마지막 접점 기준 | 전환 직전 행동 개선 | 등록 전 마지막 확인 접점 하나에 연결 |
| 보조 접점 보기 | 콘텐츠·이벤트의 도움 확인 | 매출을 분배하지 않고 접점 수·사례만 표시 |
| 미귀속 포함 전체 | 사업 전체 성과 판단 | 전체 매출과 확인 매출의 차이를 명확히 표시 |

초기 버전의 기본값은 `고객 응답 기준`이다. 이는 사람이 수기로 운영하는 환경에서 가장 설명 가능하고, 대표에게도 가장 정직한 기준이다.

## 9. 관리 화면의 CRUD

### 채널 설정

채널을 만들 때 반드시 아래 순서로 진행한다.

1. 이름과 색상
2. 유형: 유료 광고 / 콘텐츠 / 검색 광고 / 제휴·미디어 / 기타
3. 측정 프로필: 당근 광고 / 인스타그램 / 블로그 / 검색 광고 / 사용자 정의
4. 입력 지표와 월간 집계법 확인·수정
5. 표시 순서와 활성 상태

측정 프로필이 달라지면 운영 시트의 하위 지표 행이 자동으로 달라진다. 즉, 채널 CRUD는 이름 목록 관리가 아니라 **해당 채널의 측정 방식 설정**이다.

### 콘텐츠와 이벤트 생성

- `+ 빠른 입력`은 오늘의 퍼널·기존 행의 수치를 바로 기록한다.
- 각 블록의 `+ 콘텐츠`, `+ 광고 소재`, `+ 이벤트`는 대상 자산을 만든 뒤 즉시 해당 행으로 포커스한다.
- 이벤트는 채널 선택을 강제하지 않는다. 필요한 경우에만 연결 채널을 참고 정보로 둔다.

1. SaaS 상단 바와 월 선택 UI

## 11. 구현 승인 기준

- 9월 화면을 열면 `2026년 9월`, 월 합계, 1~30일 날짜가 항상 동시에 보인다.
- 사용자는 마우스만으로도, 키보드만으로도 한 날짜의 연속 지표를 빠르게 입력할 수 있다.
- 당근 소재 세 개와 인스타 게시물 하나를 추가했을 때 서로 다른 지표 행과 다른 집계법이 자동 적용된다.
- 상담·등록이 광고 행에 나타나지 않고 학원 전체 퍼널에서 단 한 번만 기록된다.
- 설명회와 커피차를 이벤트로 생성해 비용과 결과를 기록해도 채널 목록에는 들어가지 않는다.
- 고객 답변으로 확인된 등록 하나를 콘텐츠·광고·이벤트 접점과 연결하고, 매출·CAC·ROAS를 근거와 함께 볼 수 있다.
- 출처 미확인 상담/등록은 임의 채널로 귀속되지 않고, 분석 화면에서 전체 결과와 구분된다.
- 해당 월을 PDF/Excel로 내보냈을 때 표의 수치, 집계 방식, 비용 합계가 화면과 일치한다.
