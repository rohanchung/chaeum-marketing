# 구매 목록과 이벤트 물품 원가

- 이벤트 옆 구매 메뉴: 구매·결제일, 물품명, 수량, 결제액, 단가, 사용량, 잔량, 연결 이벤트, 메모와 수정/휴지통/복원.
- 같은 물품도 구매 건마다 별도 단가를 유지한다. 총 결제액에는 배송·제작비를 포함한다.
- 이벤트 작성/수정에서 구매 건을 선택하고 실제 사용 수량을 입력한다. 이벤트와 사용 내역은 단일 RPC 트랜잭션으로 저장한다.
- 사용량 초과 및 사용 중인 구매 삭제를 서버에서 차단한다. 수량 감소/사용 내역 제거는 반납 처리다. 이벤트 취소·휴지통만으로 사용량을 없애지 않는다.
- 구매 결제액은 구매일 전체 마케팅 지출과 비용 원장에 한 번 반영한다. 원장의 구매 수정 버튼은 구매 기록을 수정한다.
- 이벤트 원가 = 물품 사용량 × 구매 건 단가 + 이벤트에 연결된 지급 완료 직접 비용. 이벤트 카드, 날짜 상세, 기존 운영시트 이벤트 표시에서 확인한다. 대시보드 구조는 유지한다.
- 분석의 이벤트별 기간 비용에는 시작일 기준 물품 원가를 포함한다. 전체 현금 지출과 추세에 물품 사용 원가를 다시 합산하지 않는다. 이벤트 카드/편집의 원가는 이벤트 전체 기준이다.
- 예: 볼펜 500개 100,000원 구매, 150개 사용, 장소비 50,000원 → 잔량 350개, 이벤트 원가 80,000원, 총 지출 150,000원.
- 새 백업에는 구매/사용 내역을 포함한다. 이전 백업 복원 시 이 두 테이블은 보존한다.

## 검증

- Node 테스트 34개 통과: 구매/이벤트 중복 합산 방지, 월 경계, 단가 차이, 반납 및 삭제 이벤트 사용량 포함.
- 변경 TypeScript/React 파일 ESLint 및 GitHub Pages용 정적 빌드 통과.
- 실제 앱 소유자 권한으로 구매와 이벤트 사용 저장, 수량 초과 시 이벤트 생성까지 롤백, 구매 수량 축소/삭제 차단, 사용량 수정, 반납 검증. 테스트 트랜잭션 전부 롤백.
- 신규/기존 백업 복원과 외부 사용자 조회/저장 차단 검증. SQL 회귀 테스트는 supabase/tests/event_purchases*.sql.
- Supabase 전용 프로젝트 nwxbfmycimrxaovemela에 두 migration 적용, 원격 버전과 파일명 일치.
- 보안 Advisor: 새 RLS 문제 없음. 기존 Auth 유출 비밀번호 보호 비활성 경고는 유지. [기존 설정 안내](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
- 브라우저 화면 조작 없이 내부 계산/DB/빌드로 검증. 커밋·푸시는 사용자 GitHub Desktop에서 수행.
