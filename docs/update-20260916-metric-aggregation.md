# 기록이 있는 지표의 집계 방식 변경

## 사용자 확인과 수정

- 로한은 당근 단골수에 ‘그날 새로 늘어난 단골 수’를 입력한다. 기존 latest 설정은 입력 의도와 달랐다.
- bizProfileRegulars를 daily로 변경하고 신규 템플릿도 동일하게 수정했다. 원본 관측은 변경하지 않았다. 9월 현재 1+2+1=4명, 실제 입력 3건을 DB에서 확인했다.
- private.validate_mkt_row의 전면 변경 금지를 좁혔다. 기록이 있어도 daily/cumulative/latest 사이 집계 방식 변경을 허용한다.
- 기존 기록의 연결 대상(채널/범위/키), 단위는 보존한다. 직접 입력값이 있는 지표를 ratio로 바꿔 기록을 숨기는 전환은 차단한다. UI도 해당 옵션을 잠그고 이유를 표시한다. 순위는 기존 rank/latest 계약, 학원 퍼널은 daily 계약을 유지한다.
- 새 옵션 문구: 기간 합계·일별 신규 수 합산 / 누적 총수·마지막 값 / 최근 관측값. 1,2,1의 합계는4, 마지막 값은1이라는 예시를 제공한다.
- 집계 방식 변경 후 데이터 재조회로 시트, 대표 요약, 현재 보고서·내보내기가 다시 계산된다. 합계가 DB에 별도로 중복 저장되는 구조가 아니므로 관측 레코드를 수정하거나 변환하지 않는다.
- 파생 비율은 참조 원시 지표의 현재 집계 방식을 사용하도록 수정했다. daily만 찾던 조건 때문에 집계 방식 변경 후 비율이 비는 문제를 방지한다. 순위/다른 계산식은 피연산자에서 제외한다.
- 비용 합산용 지표를 daily 이외로 바꾸면 비용 합산에서도 제외됨을 폼에 표시한다. 기존 저장 보고서는 당시 수치인 스냅샷으로 보존한다.
