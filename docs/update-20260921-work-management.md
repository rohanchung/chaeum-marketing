# 업무·프로젝트 관리 1단계

작성일: 2026-09-21
제작방: 현재 제작방

## 결정

로한 마케팅에 업무 영역·프로젝트·Task를 저장하는 업무 페이지를 추가했다. 현재 첫 업무 영역은 `채움영어 풍무캠퍼스 마케팅`으로 자동 생성된다. 행정사 전용 모델과 다중 사용자 협업은 이번 범위에 넣지 않았다.

Task는 내가 만든 업무, 원장님·다른 선생님에게 요청받은 업무, 반복 업무의 출처를 구분한다. 요청받은 업무는 요청자 이름과 요청 내용을 기록할 수 있고, 실행 예정일과 마감일은 별도로 저장한다.

## 구현

- `mkt_work_areas`, `mkt_work_projects`, `mkt_tasks`, `mkt_work_links` 테이블과 workspace RLS를 추가했다.
- 업무 페이지에 오늘·프로젝트·전체·요청받은 업무·반복 업무 필터를 추가했다.
- 목록·프로젝트 타임라인·월간 캘린더 보기를 추가했다.
- 프로젝트와 Task의 기본 CRUD, 상태·우선순위·요청자·메모·처리 결과·다음 행동을 연결했다.
- Task 수정 화면에서 업무를 휴지통으로 보내고 원본 이력을 보존할 수 있다.
- 대시보드 상단에 오늘의 프로젝트 활동을 표시하고 바로 완료 처리할 수 있게 했다.
- 대시보드 하단에 진행 중 프로젝트와 미완료 Task 수를 요약했다.
- 운영시트 날짜 헤더에 해당 날짜의 Task 수를 작은 숫자로 표시했다.
- Task 완료나 프로젝트 상태 변경은 기존 비용·퍼널·매출·ROI 계산을 변경하지 않는다.
- 기존 활동 기록을 Task로 복제하지 않고, 프로젝트 상세에서 `mkt_work_links`로 이벤트·채널·콘텐츠·집행·구매 원본을 연결·해제할 수 있게 했다.
- 기존 백업 복원 RPC는 교체하지 않고, 인증된 앱 복원 흐름에서 새 업무 테이블만 순서대로 추가 복원하도록 했다. 이전 v3 백업에 업무 키가 없어도 기존 복원은 계속 동작한다.

## 제한과 다음 단계

- 반복 업무는 현재 출처 필터와 Task 입력 구조만 준비했으며 실제 반복 규칙·회차별 완료는 다음 단계다.
- Task 자체와 운영 기록을 연결하는 세부 UI는 다음 단계다. 프로젝트와 원본 운영 기록의 연결·해제는 이번 단계에 포함했다.
- 구글 캘린더 OAuth와 일정 동기화는 아직 구현하지 않았다.
- 날짜 활동 패널은 현재 운영시트 날짜의 Task 수 표시까지 구현했고, Task·이벤트를 함께 편집하는 패널은 다음 단계다.
- 대시보드 KPI는 전체 학원 기준으로 유지한다. 프로젝트에 연결되지 않은 공통 비용을 임의로 프로젝트별 배분하지 않는다.
