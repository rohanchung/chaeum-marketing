# 업무·콘텐츠 데이터 무결성 수정 (0단계)

계획: [단계별 업데이트 계획](plan-20260929-uiux-update-roadmap.md)

## 문제

1. 휴지통 프로젝트에 연결된 업무를 열면 편집창의 프로젝트가 `미분류 업무`로 표시돼, 다른 항목만 고쳐 저장해도 프로젝트 연결이 끊겼습니다.
2. 반복 업무는 `recurrence_next_on`부터만 회차를 만들었습니다. 완료한 회차는 캘린더에서 사라졌고, 앞선 회차를 건너뛰고 뒤 회차를 완료하면 건너뛴 회차도 함께 사라졌습니다.
3. 반복 회차 저장과 반복 원본 갱신을 따로 호출해, 두 번째 호출이 실패하면 기록이 서로 어긋날 수 있었습니다.
4. 콘텐츠 채널 그룹 행의 `월간 값` 열에 소재 개수가 표시돼 월간 성과처럼 보였습니다.
5. 반복 업무 회차를 편집하면 반복 원본의 시작일이 클릭한 회차 날짜로 바뀌었습니다.

## 변경

- 편집창의 프로젝트 목록에 현재 연결된 휴지통 프로젝트를 `(휴지통) 이름`으로 남깁니다. 카드와 캘린더 바 툴팁에도 휴지통 상태를 표시합니다.
- 반복 회차는 반복 시작일부터 계산합니다. 완료한 회차는 취소선으로 남고, 지나간 미완료 회차는 기한 초과로 표시됩니다.
- `recurrence_next_on`은 “가장 이른 미완료 회차”를 뜻합니다. 모든 회차를 마치면 반복 원본이 완료 처리됩니다.
- 신규 RPC `mkt_set_task_occurrence`가 회차 저장, 다음 미완료 회차, 원본 상태를 한 트랜잭션에서 저장합니다. 미래 회차는 서버에서도 완료할 수 없습니다.
- 반복 회차를 편집하면 반복 원본을 편집합니다.
- 콘텐츠 채널 그룹 행의 월간 값은 `—`로 표시합니다. 소재 개수는 채널 이름 옆에만 표시합니다.

## DB

- migration `20260929000513_task_occurrence_completion` 적용(원격 이력과 로컬 파일명 일치). 테이블 구조는 바뀌지 않았습니다.
- 적용 전 조회 결과, 반복 업무는 휴지통의 1건뿐이라 기존 데이터에 주는 영향은 없습니다.

## 검증

- 단위 테스트 45개 통과: 완료·미완료 회차 유지, 종료일, 가장 이른 미완료 회차 계산.
- `supabase/tests/task_recurrence.sql`: 뒤 회차 완료, 되돌리기, 반복 종료, 미래 회차 거부를 원격 DB에서 트랜잭션으로 실행하고 롤백했습니다.
- TypeScript, ESLint 통과.

## 제한

- 반복 회차 `건너뛰기(skipped)`는 DB 상태로만 존재하고 화면 동작은 아직 없습니다. 표시할 때는 취소로 보여 줍니다.
