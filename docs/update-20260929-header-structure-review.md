# 전역 헤더 날짜 컨트롤·페이지 검토·구조 정리 (5단계)

계획: [단계별 업데이트 계획](plan-20260929-uiux-update-roadmap.md)

## 검토 결과 (로한 요청: 전 페이지 UI/UX 점검)

| 항목 | 발견 | 조치 |
|---|---|---|
| 날짜 컨트롤 | 모든 페이지가 같은 `month` 상태를 쓰는데, 컨트롤은 공용 툴바·업무·콘텐츠 세 곳에 따로 있었음. 헤더에는 로그아웃만 있었음 | 날짜 컨트롤과 저장 상태를 전역 헤더 오른쪽으로 이동, 페이지별 날짜 줄 삭제 |
| 기간 무관 페이지 | 구매는 전체 구매를 보여 주는데 날짜 컨트롤이 떠 있었음(눌러도 변화 없음) | 구매·로그에서는 날짜 컨트롤을 숨김 |
| 한 페이지 내 중복 버튼 | 업무: 헤더와 오른쪽 패널에 `＋ 업무` 두 개(`＋ 이벤트`도 패널에만) | 헤더에 `＋ 프로젝트 / ＋ 이벤트 / ＋ 업무`만 남김. 패널이 보는 날짜(오늘 보드면 오늘, 날짜 목록이면 그 날짜)로 추가 |
| 〃 | 대시보드: `＋ 입력` 메뉴의 채널 추가와 시트의 `＋ 채널` | 메뉴에서 채널 추가 제거. `＋ 입력`은 운영시트 도구줄로 이동 |
| 〃 | 콘텐츠: `채널 관리` 버튼이 실제로는 새 채널 추가 창을 열어 `＋ 채널 추가`와 같은 동작 | `채널 관리`는 아래 `채널·지표 관리` 패널을 열고 그 위치로 이동 |
| 제목 | 이벤트·구매·분석·리포트는 영문 머리말 + 슬로건형 큰 제목("변화를 만든 날의 기록" 등), 업무·콘텐츠는 짧은 제목 | 모든 페이지를 `페이지 이름 + 한 줄 설명` 20px 제목으로 통일 |
| 상태 표기 | 이벤트 페이지 상태가 `planned`, `completed` 영문 | 한국어(예정·진행 중·완료·취소). 라벨은 `lib/domain.ts`의 `eventStatusLabels` 하나로 공유 |
| 글자 크기 | 8~10px 글자가 93곳(콘텐츠 60, 업무 37, 대시보드 19 등 화면 기준) | 앱 전체 최소 11px로 통일. 1366×768에서 잘린 버튼·가로 넘침 없음 확인 |
| 가짜 상태 표시 | 콘텐츠 제목 옆 `● 콘텐츠·광고 소재 운영`이 저장 상태처럼 보임 | 점 제거, 설명 문구로만 표시 |
| 글꼴 | 8개 페이지 모든 요소가 이미 Pretendard(전수 검사). 배포 CSS에도 포함 | 변경 없음. 제한 참고 |

## 헤더 규칙

- 대시보드·업무·콘텐츠: 월 선택. 이벤트·분석·리포트: 일/월/연 + 기간. 구매·로그: 날짜 컨트롤 없음.
- 저장 상태는 1360px 이하에서 점만 보이고 전체 문구는 툴팁. 1100px 이하에서는 헤더 도구가 둘째 줄로 내려갑니다.
- 업무 캘린더의 Shift+휠 월 전환은 그대로이며 헤더 월과 연동됩니다.

## 구조 정리 (5단계)

- `app/page.tsx` 1,917줄 → 1,527줄: `components/ui.tsx`(BrandMark·Empty·PageTitle·DataTable), `kpis.tsx`, `analysis.tsx`, `app-header.tsx`로 분리.
- `components/task-workspace.tsx` 1,445줄 → 563줄: `task-form.tsx`(업무·프로젝트 편집), `task-row.tsx`(업무 카드), `task-shared.ts`(라벨·공용 타입), `lib/task-dates.ts`(날짜 헬퍼), `lib/task-board.ts`(반복 회차 전개 포함).
- 동작 변화 없는 이동입니다. `page.tsx`에 남은 부분은 공용 상태(데이터·저장 큐·편집기)를 쓰는 화면 조립으로, 페이지별 분리는 상태 전달 구조를 먼저 정해야 해 이번 범위에서 제외했습니다.

## 검증

- 단위 테스트 53개, TypeScript, ESLint, 프로덕션 빌드 통과.
- 1366×768 실제 데이터로 8개 페이지 확인: 헤더 도구 표시 규칙, 중복 버튼 없음, 11px 미만 글자 0곳, 잘린 버튼·가로 넘침 없음, 1180px 헤더 한 줄 유지, `채널 관리` 패널 이동.

## 제한

- Pretendard는 jsDelivr CDN에서 불러옵니다. CDN이 막히거나 느리면 시스템 글꼴로 보일 수 있습니다. 완전히 고정하려면 글꼴 파일을 프로젝트에 포함(self-host)해야 하며, 이는 로한 승인 후 진행합니다.
- 리포트는 분석 `성과` 탭과 같은 화면 + 내보내기입니다. 페이지 간 중복이라 유지했습니다.
