# 직접 광고 소재의 운영시트 묶음 하나로 통합

## 문제 (로한 제보)

네이버광고 채널(검색광고 템플릿)에 소재 `풍무캠퍼스 AD부스트#1`을 추가하면서 광고 기간 9/29~9/30을 입력하자, 운영시트의 한 소재 아래에 묶음이 두 개 생겼다.

- `일별 광고 기록`: 9/1~9/28 입력 칸, 9/29·9/30은 빗금(입력 불가)
- `풍무캠퍼스 AD부스트#1 광고`: 9/29~9/30만 입력 가능

원인: 직접 광고 채널(당근·인스타·검색광고)은 09-14 결정에 따라 "기간을 미리 정하지 않아도 어느 날이든 입력"할 수 있도록, 실제 집행이 없는 날짜마다 가상 `일별 광고 기록` 칸을 만든다. 실제 집행이 달의 일부만 덮으면 가상 칸과 실제 집행이 **각각 별도 묶음**으로 그려지고, 같은 날짜의 중복 입력을 막으려고 서로의 날짜를 막았다. 데이터 오류는 아니지만 화면에서는 중복·입력 불가로 보였다.

## 변경

- 직접 광고 채널의 소재는 광고 지표·광고비를 **한 묶음**으로 표시한다. 행은 소재 아래 바로 나온다.
- 각 날짜 칸은 그 날짜를 덮는 실제 집행(없으면 가상 칸)에 저장한다. 첫 숫자를 입력하면 이전처럼 가상 칸이 `YYYY-MM 일별 광고 기록` 집행으로 만들어진다.
- 월간 요약·일별 값은 소재의 그 달 모든 집행 기간을 합쳐 읽는다. 비율(클릭률·클릭당 비용 등)도 합친 값으로 다시 계산한다.
- 어떤 날짜도 막히지 않는다. 09-14 원칙(기간 사전 설정 없이 매일 입력, 기존 기간·기록 보존)은 그대로다.
- 직접 광고 템플릿(`paid_ad`·`social_content`·`search_ad`)이 아닌 채널은 기존처럼 집행별 묶음을 유지한다.

## 구현

- `MetricRow.segments`: 한 행이 여러 집행 기간을 가진다. `segmentFor(row, date)`가 날짜별 저장 대상을, `matchesRowPromotion`이 합산 대상을 정한다(`lib/domain.ts`).
- `metricValue`(값·비용)가 합친 행을 지원한다(`lib/analytics.ts`). 기존 단일 집행 행의 동작은 같다.
- 운영시트: 직접 광고 소재는 합친 행 하나, 붙여넣기·되돌리기도 날짜별 저장 대상을 따른다(`components/operating-sheet.tsx`).

## 검증

- 단위 테스트 71개(신규: 부분 집행 기간에서 날짜별 저장 대상, 두 기간 값 합산, 광고비 합산), TypeScript, ESLint, 프로덕션 빌드 통과.
- DB 변경 없음. 기존 집행·값·비용 기록은 그대로다.
