# 운영시트 저장이 멈추는 문제 (요청 제한 시간)

## 증상 (로한 제보, 10/2)

10월로 넘어간 뒤 대시보드 시트에 숫자를 입력해도 저장되지 않음.

## 확인한 사실

- 서버 로그: 10/1 11:15~11:56(KST) 시트 저장 수십 건 성공(9/30 칸 입력). **10/2에는 시트 저장 요청이 서버에 한 건도 도착하지 않음.** 같은 시간 업무 추가·이벤트 저장은 정상 도착.
- 배포 사이트에는 최신 코드(33eaff3)가 올라가 있음(배포 번들 확인).
- 같은 코드로 로컬에서 10월 시트(학원 퍼널, 광고 소재 첫 입력 시 `2026-10 일별 광고 기록` 생성)를 입력하면 저장 요청이 정상적으로 나감(요청을 가로채 실제 저장 없이 확인).
- 시트 입력만 **한 번에 하나씩 저장하는 대기열**을 거치고, 업무·이벤트 저장은 대기열을 쓰지 않음. 요청에 제한 시간이 없어, 앞선 저장 요청 하나가 응답 없이 멈추면(탭을 연 채 절전·네트워크 전환 등) 이후 시트 입력은 서버로 나가지도, 오류를 띄우지도 않고 계속 대기함. 10월 자체의 날짜 처리 문제는 아님.

## 변경

- 모든 Supabase 요청에 **30초 제한 시간**. 응답이 없으면 “서버 응답이 없습니다. 다시 시도하세요.”로 실패하고 시트에 오류가 표시됨(`lib/supabase.ts`).
- 시트 저장 대기열은 앞선 저장을 **최대 45초**만 기다리고 다음 입력을 처리(`app/page.tsx`).
- 요청이 끊겨도 서버가 이미 저장했을 수 있으나, 시트 저장은 같은 값 재저장에 안전하므로 다시 입력하면 된다.

## 검증

- 단위 테스트 74개(신규 `request-timeout.test.cjs`: 멈춘 요청 실패, 정상 응답 통과, 호출자 취소 유지), TypeScript, ESLint, 프로덕션 빌드 통과.
- 로컬 재현: 첫 저장 요청을 응답 없이 멈추게 한 상태에서 다음 칸 입력 → 30초 뒤 첫 요청이 끊기고 두 번째 저장 요청이 바로 전송됨. 실제 DB에는 저장하지 않음(10월 값·집행 수 변화 없음 확인).

## 사용자 조치

- 배포 전에도 페이지를 **새로고침(F5)** 하면 멈춘 대기열이 비워져 바로 입력된다.
