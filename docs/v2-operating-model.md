# 채움 마케팅 운영 시트 v2 설계

## 문제 진단

초기 화면은 월간 지표를 간단히 입력하는 데모였다. 운영 화면으로 사용하기에는 다음 문제가 있다.

1. 기간 맥락과 월 이동이 약해 현재 보고 있는 데이터 범위를 즉시 알 수 없다.
2. 채널을 만들고 수정하고 비활성화할 수 없다.
3. 콘텐츠 채널의 성과를 콘텐츠 단위로 누적하고 비교할 구조가 없다.
4. 일회성 설명회, 방송 출연, 커피차처럼 채널이 아닌 사건을 채널 행에 억지로 넣고 있다.
5. 상담과 등록은 학원 전체의 일일 실적이며, 광고·콘텐츠의 성과와 동일한 방식으로 귀속하면 왜곡된다.
6. 입력 화면과 관리 화면의 위계가 없어 운영자의 판단 흐름을 지원하지 못한다.

## 운영 원칙

- 한 화면에서 월간 운영을 끝낸다. 화면 전환이 아니라 우측 패널과 하단 작업 패널을 사용한다.
- 날짜가 가로축, 운영 대상이 세로축인 스프레드시트 경험은 유지한다.
- 상담과 등록은 `일일 학원 퍼널`로 한 번만 입력한다. 채널 성과에는 노출과 유입, 콘텐츠 반응만 기록한다.
- 채널은 지속적으로 운영되는 유입 경로다. 콘텐츠는 채널의 하위 자산이다. 이벤트는 채널과 별도의 일회성 사건이다.
- 광고비, 제작비, 굿즈비, 이벤트비는 비용 원장에서 개별 항목으로 남기고 월간 합계에 연결한다.

## 화면 구조

### 1. 월간 컨트롤 룸

상단에는 `2026년 9월`처럼 명확한 기간 표시와 이전 달, 이번 달, 다음 달 이동을 둔다. 같은 줄에 PDF와 Excel 보고서, 관리 버튼을 둔다.

상단 KPI는 학원 전체 기준이다.

- 유입
- 상담: 카카오톡, 전화, 방문으로 세부 입력
- 등록: 현장 등록
- 총 집행액
- 전환율: 상담 대비 등록

### 2. 일일 학원 퍼널

컨트롤 룸 최상단의 고정 행이다. 날짜 칸을 누르면 해당 날짜의 유입, 카카오 상담, 전화 상담, 방문 상담, 등록, 메모를 입력한다. 이 값은 채널 행에 중복되지 않는다.

### 3. 채널과 콘텐츠 트리

지속 채널은 좌측에 굵은 상위 행으로 표시한다.

- 당근 광고: 채널 행 아래에 캠페인 또는 광고 소재 행
- 네이버 블로그: 채널 행 아래에 게시글 행
- 인스타그램: 채널 행 아래에 게시물 또는 릴스 행
- 제휴·미디어: 협력처 또는 출연 건 행

상위 채널 행은 하위 콘텐츠의 합계를 보여 준다. 하위 행은 노출, 유입, 광고비와 메모를 날짜별로 기록한다.

### 4. 이벤트 타임라인

설명회, 커피차, 방송 출연, 체험 수업 같은 사건은 별도 `이벤트` 섹션에 둔다. 이벤트는 시작·종료일, 장소, 상태, 담당, 비용, 결과 메모를 가진다. 기간 중 날짜 칸에 사건의 반응과 비용을 기록할 수 있지만 지속 채널 합계에는 포함하지 않는다.

### 5. 우측 빠른 입력 패널

어느 칸을 눌러도 같은 입력 패널이 열린다. 대상 유형에 따라 입력 항목만 달라진다.

- 일일 퍼널: 상담 경로와 등록
- 채널/콘텐츠: 노출, 유입, 광고비, 콘텐츠 URL, 메모
- 이벤트: 참여/신청, 유입, 직접 비용, 결과
- 비용: 광고, 제작, 굿즈, 이벤트, 대행사, 기타

### 6. 관리 오버레이

상단 `관리` 버튼에서 페이지 이동 없이 채널, 콘텐츠, 이벤트, 비용 항목을 CRUD 한다. 삭제 대신 비활성화와 감사 로그를 기본으로 한다.

## 데이터 모델 변경

### 새 테이블

`daily_funnel_records`

- workspace_id, metric_date
- inflows, kakao_consultations, phone_consultations, visit_consultations, enrollments
- notes
- 날짜와 작업공간 조합은 하나만 허용

`event_metric_records`

- workspace_id, event_id, metric_date
- inquiries, attendees, inflows, direct_cost, notes

### 기존 테이블 확장

`contents`에 channel_id와 campaign_id를 추가한다. 콘텐츠는 하나의 주 채널에 속하고, 필요 시 캠페인과 연결한다.

`performance_records`는 채널 또는 콘텐츠 성과 전용으로 사용한다. 상담과 등록 입력은 신규 일일 퍼널 테이블로 이동한다.

## 구현 순서

1. v2 데이터 모델과 RLS 정책을 추가하고 실제 Supabase에 적용한다.
2. 월간 컨트롤 룸의 기간 UI, KPI, 일일 퍼널 고정 행을 만든다.
3. 채널 CRUD와 콘텐츠 하위 트리를 연결한다.
4. 이벤트 타임라인과 비용 원장을 연결한다.
5. 보고서를 v2 집계 기준으로 교체한다.

## 완료 기준

- 월을 이동하면 화면의 모든 숫자가 같은 기간으로 갱신된다.
- 상담과 등록은 날짜별로 한 번만 입력한다.
- 블로그/인스타그램 콘텐츠마다 별도 성과를 입력하고 채널 합계를 볼 수 있다.
- 이벤트는 채널과 별도 객체로 생성하고 비용과 결과를 남길 수 있다.
- 채널, 콘텐츠, 이벤트, 비용 항목은 화면 전환 없이 CRUD 할 수 있다.
