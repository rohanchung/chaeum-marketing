# 채움 마케팅 운영 시트 v2 설계

## 문제 진단

초기 화면은 월간 지표를 간단히 입력하는 데모였다. 운영 화면으로 사용하기에는 다음 문제가 있다.

1. 기간 맥락과 월 이동이 약해 현재 보고 있는 데이터 범위를 즉시 알 수 없다.
2. 채널을 만들고 수정하고 비활성화할 수 없다.
3. 콘텐츠 채널의 성과를 콘텐츠 단위로 누적하고 비교할 구조가 없다.
4. 일회성 설명회, 방송 출연, 커피차처럼 채널이 아닌 사건을 채널 행에 억지로 넣고 있다.
5. 상담과 등록은 학원 전체의 일일 실적이며, 광고·콘텐츠의 성과와 동일한 방식으로 귀속하면 왜곡된다.
6. 입력 화면과 관리 화면의 위계가 없어 운영자의 판단 흐름을 지원하지 못한다.

## 운영 원칙

- 한 화면에서 월간 운영을 끝낸다. 화면 전환이 아니라 우측 패널과 하단 작업 패널을 사용한다.
- 날짜가 가로축, 운영 대상이 세로축인 스프레드시트 경험은 유지한다.
- 상담과 등록은 `일일 학원 퍼널`로 한 번만 입력한다. 채널 성과에는 노출과 유입, 콘텐츠 반응만 기록한다.
- 채널은 지속적으로 운영되는 유입 경로다. 콘텐츠는 채널의 하위 자산이다. 이벤트는 채널과 별도의 일회성 사건이다.
- 광고비, 제작비, 굿즈비, 이벤트비는 비용 원장에서 개별 항목으로 남기고 월간 합계에 연결한다.

## 기존 엑셀에서 반드시 계승할 입력 경험

기존 `다니엘T 마케팅 지표` 파일은 새 서비스가 따라야 할 핵심 운영 경험을 이미 갖고 있다.

- `A4`에서 행을 고정하고, 날짜는 수평으로 길게 이어진다.
- 왼쪽에는 채널, 콘텐츠 제목, 세부 지표가 계층적으로 쌓인다.
- 한 콘텐츠의 일별 숫자를 같은 행에서 즉시 입력한다. 별도 입력 화면으로 이동하지 않는다.
- 월 합계 열을 각 월의 시작에 두고, 입력값은 같은 행에서 곧바로 누적 결과를 확인한다.
- 학원 전체 상담·등록, 콘텐츠별 성과, 오프라인 비용, 광고 세부 지표를 한 월간 캔버스에서 함께 보되 서로 다른 행 블록으로 분리한다.

새 서비스는 이 스프레드시트 조작감을 기본으로 두고, 자동 저장·권한·이벤트·보고서·감사 로그만 웹 SaaS 수준으로 확장한다.

## 화면 구조

### 1. 월간 컨트롤 룸

상단에는 `2026년 9월`처럼 명확한 기간 표시와 이전 달, 이번 달, 다음 달 이동을 둔다. 같은 줄에 PDF와 Excel 보고서, 관리 버튼을 둔다.

상단 KPI는 학원 전체 기준이다.

- 유입
- 상담: 카카오톡, 전화, 방문으로 세부 입력
- 등록: 현장 등록
- 총 집행액
- 전환율: 상담 대비 등록

### 2. 일일 학원 퍼널

컨트롤 룸 최상단의 고정 행이다. 날짜 칸을 누르면 해당 날짜의 유입, 카카오 상담, 전화 상담, 방문 상담, 등록, 메모를 입력한다. 이 값은 채널 행에 중복되지 않는다.

### 3. 채널과 콘텐츠 트리

지속 채널은 좌측에 굵은 상위 행으로 표시한다.

- 당근 광고: 채널 행 아래에 캠페인 또는 광고 소재 행
- 네이버 블로그: 채널 행 아래에 게시글 행
- 인스타그램: 채널 행 아래에 게시물 또는 릴스 행
- 제휴·미디어: 협력처 또는 출연 건 행

상위 채널 행은 하위 콘텐츠의 합계를 보여 준다. 하위 행은 노출, 유입, 광고비와 메모를 날짜별로 기록한다.

### 4. 이벤트 타임라인

설명회, 커피차, 방송 출연, 체험 수업 같은 사건은 별도 `이벤트` 섹션에 둔다. 이벤트는 시작·종료일, 장소, 상태, 담당, 비용, 결과 메모를 가진다. 기간 중 날짜 칸에 사건의 반응과 비용을 기록할 수 있지만 지속 채널 합계에는 포함하지 않는다.

### 5. 우측 빠른 입력 패널

어느 칸을 눌러도 같은 입력 패널이 열린다. 대상 유형에 따라 입력 항목만 달라진다.

- 일일 퍼널: 상담 경로와 등록
- 채널/콘텐츠: 노출, 유입, 광고비, 콘텐츠 URL, 메모
- 이벤트: 참여/신청, 유입, 직접 비용, 결과
- 비용: 광고, 제작, 굿즈, 이벤트, 대행사, 기타

### 6. 관리 오버레이

상단 `관리` 버튼에서 페이지 이동 없이 채널, 콘텐츠, 이벤트, 비용 항목을 CRUD 한다. 삭제 대신 비활성화와 감사 로그를 기본으로 한다.

## 데이터 모델 변경

## 채널별 지표 체계

플랫폼의 원본 지표를 억지로 하나의 숫자로 통일하지 않는다. 각 채널은 아래 세 층으로 기록한다.

1. 공통 퍼널: 학원 전체의 일일 유입, 상담, 등록
2. 원본 지표: 해당 채널 또는 콘텐츠에서 실제 제공하는 수기 입력 값
3. 계산 지표: 원본 지표로 자동 계산하는 비율과 단가

### 공통 분류

| 분류 | 예시 | 입력 여부 |
|---|---|---|
| 도달 | 노출수, 조회수, 도달 | 채널별 원본 입력 |
| 유입 의도 | 클릭수, 프로필 방문, 외부 링크 클릭 | 채널별 원본 입력 |
| 반응 | 당근 반응, 좋아요, 댓글, 저장, 공유 | 채널별 원본 입력 |
| 비용 | 광고비, 제작비, 이벤트 직접비 | 비용 원장 입력 |
| 학원 전환 | 카카오/전화/방문 상담, 등록 | 일일 퍼널에서만 입력 |

### 채널 등록 시 선택하는 측정 프로필

채널을 만들 때 이름만 입력하지 않는다. `측정 프로필`을 먼저 고르면 입력 패널과 콘텐츠 하위 행의 항목이 달라진다. 운영자는 기본 항목을 끄거나 켜고, 필요하면 직접 지표를 추가할 수 있다.

#### 유료 광고 - 당근 광고 예시

수기 입력 항목

- 노출수
- 클릭수
- 반응수
- 지출
- 광고 소재별 제목과 상태

자동 계산 항목

- 클릭률 = 클릭수 / 노출수
- 반응률 = 반응수 / 클릭수
- 반응당 비용 = 지출 / 반응수
- 클릭당 비용 = 지출 / 클릭수

광고 채널 아래에는 광고 소재를 하위 행으로 만든다. 당근 화면의 세 개 광고처럼 소재별 노출·클릭·반응·지출을 기록하고, 상위 `당근 광고` 행은 합계를 보여 준다.

#### 소셜 콘텐츠 - 인스타그램 예시

수기 입력 항목

- 조회수, 도달
- 좋아요, 댓글, 저장, 공유
- 프로필 방문, 외부 링크 클릭, 비즈니스 주소 클릭
- 제작비 또는 부스팅 비용

자동 계산 항목

- 게시물 반응 = 좋아요 + 댓글 + 저장 + 공유
- 참여율 = 게시물 반응 / 도달
- 프로필 전환율 = 프로필 방문 / 조회수
- 링크 전환율 = 외부 링크 클릭 / 프로필 방문

인스타그램 채널 아래에는 릴스·피드·스토리 등 게시물별 행을 만든다. `게시물 반응 15`처럼 플랫폼이 준 합계는 원본으로 보관하고, 하위 반응도 함께 기록해 원인을 분석할 수 있게 한다.

#### 블로그 콘텐츠 예시

- 조회수, 검색 노출, 평균 체류, 공감, 댓글, 저장/공유, 프로필 또는 상담 링크 클릭
- 게시글별 URL, 발행일, 키워드, 제작비

#### 검색 광고 예시

- 노출수, 클릭수, 클릭률, 평균 클릭비용, 지출, 전환 이벤트

#### 이벤트·오프라인 예시

- 신청, 참석, 현장 문의, 유입, 직접비
- 장소, 일정, 담당, 결과 메모

### 지표 설정의 데이터 규칙

- 원본 입력값과 자동 계산값을 구분한다. 계산값은 직접 수정할 수 없다.
- 0은 실제 0이고, 빈 칸은 미입력이다. 보고서에서 둘을 구분한다.
- 플랫폼 화면의 집계 기간을 기록한다. 일일 수치가 아닌 기간 집계라면 해당 기간과 데이터 출처를 메모로 남긴다.
- 채널·콘텐츠 성과는 일일 퍼널의 상담/등록 숫자를 임의로 복제하지 않는다. 직접 귀속이 명확한 경우에만 별도 어트리뷰션 기록으로 남긴다.

### 지표별 월간 집계 방식

기존 엑셀처럼 지표마다 집계 방식이 달라야 한다. 월간 숫자를 모두 더하면 인스타그램의 누적 조회수처럼 잘못된 결과가 나온다.

| 집계 방식 | 사용 예시 | 의미 |
|---|---|---|
| 합계 | 당근 노출, 클릭, 반응, 지출, 상담, 등록, 이벤트 직접비 | 일자별 발생값을 더한다 |
| 최대값 | 인스타 조회수, 도달, 프로필 활동처럼 누적 스냅샷인 값 | 해당 월의 마지막/가장 큰 누적값을 사용한다 |
| 평균 | 클릭당 비용, 평균 체류 시간, 평균 클릭 비용 | 입력된 일자 평균을 계산한다 |
| 최신값 | 팔로워 수, 광고 상태, 재고처럼 현재 상태가 중요한 값 | 기간의 마지막 입력값을 사용한다 |

사용자가 채널을 만들 때 선택한 측정 프로필에는 각 항목의 입력 방식과 월간 집계 방식이 함께 들어간다. 따라서 인스타 콘텐츠는 기본적으로 최대값, 당근 광고는 합계로 동작하고 필요하면 채널별로 조정한다.

### 구현용 데이터 확장

`channels`에 `measurement_template`을 둔다. 예: `paid_ad`, `social_content`, `blog_content`, `search_ad`, `event`, `referral`.

`channel_metric_profiles`는 채널별로 활성화할 원본 입력 항목, 단위, 순서, 필수 여부를 저장한다. 채널 생성 시 선택한 측정 프로필의 기본 항목을 복제하고, 이후 채널별로 수정한다.

각 지표 정의에는 `aggregation_method`를 저장한다. 값은 `sum`, `max`, `average`, `latest` 중 하나다. 이 값이 월 합계·Excel·PDF 보고서의 집계 규칙이 된다.

`metric_definitions`와 `custom_metric_values`는 기존의 확장 가능한 지표 저장소로 유지한다. `channel_metric_profiles`가 어떤 지표를 해당 채널의 입력 패널에 보여 줄지 결정한다.

### 새 테이블

`daily_funnel_records`

- workspace_id, metric_date
- inflows, kakao_consultations, phone_consultations, visit_consultations, enrollments
- notes
- 날짜와 작업공간 조합은 하나만 허용

`event_metric_records`

- workspace_id, event_id, metric_date
- inquiries, attendees, inflows, direct_cost, notes

### 기존 테이블 확장

`contents`에 channel_id와 campaign_id를 추가한다. 콘텐츠는 하나의 주 채널에 속하고, 필요 시 캠페인과 연결한다.

`performance_records`는 채널 또는 콘텐츠 성과 전용으로 사용한다. 상담과 등록 입력은 신규 일일 퍼널 테이블로 이동한다.

## 구현 순서

1. v2 데이터 모델과 RLS 정책을 추가하고 실제 Supabase에 적용한다.
2. 월간 컨트롤 룸의 기간 UI, KPI, 일일 퍼널 고정 행을 만든다.
3. 채널 CRUD와 콘텐츠 하위 트리를 연결한다.
4. 이벤트 타임라인과 비용 원장을 연결한다.
5. 보고서를 v2 집계 기준으로 교체한다.

## 완료 기준

- 월을 이동하면 화면의 모든 숫자가 같은 기간으로 갱신된다.
- 상담과 등록은 날짜별로 한 번만 입력한다.
- 블로그/인스타그램 콘텐츠마다 별도 성과를 입력하고 채널 합계를 볼 수 있다.
- 이벤트는 채널과 별도 객체로 생성하고 비용과 결과를 남길 수 있다.
- 채널, 콘텐츠, 이벤트, 비용 항목은 화면 전환 없이 CRUD 할 수 있다.
